## 二、功能全貌

### A. 数据体检（只读）

库概览、15 字段覆盖率、唯一性、孤儿分类、URL 规范性、推断质量、分类分布、
图标引用一致性、时间线。

### B. 受控修复

URL 归一化、补充 aliases、孤儿分类重指派、清理失效图标、重排 `sortOrder`、
标记人工校正。

**作用范围**（v0.3）：可限定到某个分类或某个方向，只约束字段级修复。
排序重排刻意不受范围限制——只重排一部分会让序号在边界处重复。

### C. 重复合并（v0.3）

- 判据：归一化网址相同或名称相同；用并查集处理传递性（A 同网址 B、B 同名 C → 同一组）
- 默认保留：信息更全 → 更新更近 → 访问更多 → id 字典序
- 合并规则：别名/用途取并集、访问量相加、描述取最长、空字段互相补齐、定位取高置信、创建取最早
- 可逐组改保留项，也可逐字段指定取谁

### D. 导入导出

导出站点（全量/切片，JSON/CSV）、导出报告（Markdown/JSON）、
导入（CSV/JSON，三种冲突策略，**覆盖前显示字段级 diff**）。

### E. 趋势（v0.3）

显式记录（按钮或写操作成功后），服务端自行计算摘要，最多保留 100 个点，
同问题数 5 分钟内去重。

## 五、使用

后台 →「数据」分组 → **数据管理**（快捷键 `g m`），或 `?tab=data-manager`。

**建议节奏**

1. 看概览与趋势，判断这轮要不要处理
2. 勾选低风险修复 → 生成计划 → 核对 diff → 应用
3. 需要时查重复 → 逐组确认保留项 → 合并
4. 导入新数据前先预检，重点看「无效行」与「字段级 diff」
5. 每次处理完点一次「记录本次体检」，趋势才有意义

## 六、设计与安全边界

1. **只有一条写通道**。修复 / 导入 / 合并都只返回 `nextSites`，落库统一走
   `POST /api/sites`（CAS + 写前快照 + `sanitizeSites`）。
2. **版本闸门集中在 `useDataWrite`**。三条路径共用一份实现，不会出现「一处改了另一处忘了」。
3. **插件组锁定**。注册表 `strategy: locked` / `writable: false`。
4. **读失败不当空库**。读取异常一律 503。
5. **合并是唯一减少条数的操作**，界面显式显示「将减少 N 条」，且接口层拒绝空结果。
6. **趋势不被伪造**。摘要在服务端计算，不接受前端数字。
7. **对象身份复用**。未命中的站点返回原引用，不触发无谓重渲染。
