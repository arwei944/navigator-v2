管理后台 · 20 种中间区布局

约束：两侧栏完全不变（左侧导航 240px / 右侧信息栏 300px），只改中间区。 每张卡是一个真预览（真实令牌、真实组件尺寸，隔离在 Shadow DOM 里），不是线框图 —— 因为「风格一致性」这件事，只有在真渲染上量才作数。 点预览可放大到 1:1。

基准采样 10,633 个元素 来源 主站 4 页 + 后台不变部分 后台现状参考 1,881 个元素 / 13 面板 布局 20 种

一、一致性怎么量（口径可复算）

「一致性」不靠印象打分。每个布局用到的每个样式值，都拿去和产品真实用过的值域比对， 落进三档之一：主流（产品令牌值，或主站采样里占比 ≥10% 的取值）、 次要（产品任一处用过、但不是主流用法 —— 后台现状也算「用过」）、 新增（主站与后台现状里都没出现过）。 这些数字是页面加载时从每个预览的 Shadow DOM 里实测出来的，不是写死的。

属性权重为什么给这个权重
打分公式：每个「元素 × 属性」的取值先判档 —— 主流 = 1.0、次要 = 0.5、新增 = 0， 按该属性在预览里的使用次数加权平均，再按上表的属性权重合成 0–100。
为什么分档而不是纯按频次：基线分布极度倾斜（0 圆角占 72%、14px 占 54%）， 纯频次加权会把每一个布局都压到 20 多分，分数就失去分辨力了。 分档保留排序能力，同时把「主流 / 次要 / 新增」三类占比摆在明面上 —— 比一个笼统的总分更好核。
为什么要把产品令牌值并进判据：基线是采样，不是规范。采样时某个令牌恰好没被渲染到 （强调色只在下拉选中时出现、页面根元素底色不在 querySelectorAll('*') 里）， 它就会缺席，「用强调色做按钮底色」这种再正常不过的写法会被误判成「新增」。 实测：--accent / --accent-light / --bg-primary 在采样里都缺席。
为什么基准不含后台中间区：中间区正是这次要换掉的东西，拿它当基准等于自己证明自己。 所以基准 = 主站 4 个页面（首页 / 收藏 / 洞察 / 图谱）的整页 + 后台里不变的部分（左栏 / 右栏 / 头部）。 后台 13 个面板的现状另存一份参考，见第三节。
哪些是实测、哪些是声明：一致性分、新增原语、强调色占比是实测； 交互点击数、组件复用数、改造面是我按结构推导的声明值，写在卡片上供你核对 —— 两者不混着算。

二、基线长什么样（这是打分的分母）

先说一个不好听但重要的事实：现有后台自己就在漂 —— 11 种圆角、14 种字号、 #2563eb 与主站 --accent #0071e3 两套蓝并存、间距里混着 6.5px / 11px 这种非栅格值。 所以「一致性」不是一个绝对的好，本页量的是相对这套视觉语言的贴合度： 越贴近主流值域，越像是同一个产品长出来的。

三、20 种布局

按一致性分从高到低排序。先说结论：20 个都落在 80–89 分——因为它们的预览都是我按产品令牌写的， 也就是说没有一个是风格上的外来物；分数差异只反映「谁烧掉的设计语言值更多」（结构越复杂、越密集， 用到的次要值越多，分略低）。所以这份分数用来排除异类，不用来分高下 —— 真正在 20 个之间做选择，看的是下面的结构与交互成本两列。
