Frontend Comparison & Synthesis

三方前端全面对比
参考站 huarun.win · V5 改造前 · V6 现状

这份报告回答一个问题：把三条前端各自的优点合到一起，应该长什么样。 参考站是「视觉与信息架构的标杆」，V5 是「交互密度与个性化最丰满的一版」，V6 是「已对齐参考站、但为对齐付出了一些体验代价的现状」。 结论不是三选一，而是以 V6 为骨架，回收 V5 被误删的交互能力，并补齐两处尚未对齐的规格。

01

结论速览

参考站赢在「形」

  • 玻璃态 token 体系 + 内高光 + 径向光晕，双主题完整
  • 双层导航：顶栏 5 个域 + 228px 侧栏 29 分类
  • 卡片双形态（桌面网格 / 移动 iOS 列表行）与悬停位移主色环
  • 文档流整页滚动 + 独立详情路由 + 页脚分类入口，利于 SEO

V5 赢在「用」

  • 悬停即看右侧详情面板 —— 零点击成本
  • 站内搜索建议下拉：高亮 + 键盘上下选择 + 结果计数
  • 侧栏可折叠成 60px 图标态、可拖拽调宽 160–400px
  • 统计条 / 多预设主题换肤 / 时钟 / 天气 / Google 搜索

V6 赢在「底」

  • 形态已对齐参考站，且滚动模型、断点、卡片双形态全部到位
  • 筛选层（分类 + 收藏 + 健康状态）与 URL query 双向同步
  • 本地覆盖层 + 会话同步 + 探活分级 + 懒加载，数据能力远超参考站
  • 个性化全保留：收藏 / 待办 / 历史 / 回收站 / 批量 / 拖拽 / 命令面板 / 后台
融合原则：V6 做骨架，V5 做血肉，参考站做标尺。 骨架（布局 / 滚动 / 卡片 / 断点）已经是三方最优，不动；血肉（详情、搜索、侧栏操作、主题）从 V5 回收；标尺（规格数值）用参考站校验，只补未对齐项。
对齐过程中确有「误伤」。V6 为对齐参考站，把 V5 的悬停详情面板、搜索建议下拉、侧栏折叠/拖拽、分类分组折叠、多预设主题一并舍掉了 —— 这些并非参考站的缺陷，而是本地独有的增量能力。本报告的融合方案主要是把它们在不动骨架的前提下装回来。

04

逐项详解

对每个有分歧的维度，列出三方做法、各自得失，以及融合后的具体动作。

4.1 布局骨架与滚动模型

采用 V6

这是三方差异最大、也最不该再动的一层。V6 已经把它做对了。

参考站

顶栏 52px 吸顶 + 228px 侧栏 + 文档流整页滚动 + 页脚。滚动条属于文档，移动端可自然下拉刷新、可被搜索引擎抓取。

整页滚动，移动端与 SEO 友好 无个性化，骨架偏「展示」而非「工具」

V5

.app-layout 三栏 height:100vh; overflow:hidden，滚动发生在中间容器内部；右栏 280px 可折叠到 0。

三栏同时可见，信息密度高 内部滚动导致移动端体验差、整页 SEO 差；断点 1440/1024/768 与参考站三段式不一致

V6

header.topbar → div.app-shell(228px + 1fr) → main.catalog → SiteFooter，文档流滚动，背景叠三团径向光晕。

与参考站逐字对齐（M8 七宽度回归：桌面五档列宽/内边距/顶栏全部相等） —
融合动作：不动。V6 骨架保留，作为其余一切改造的承载面。

4.2 导航结构：双层已就位，但丢了「分组」与「折叠」

V6 基底 + 回收 V5

V6 的「顶栏放域 + 侧栏放分类」与参考站一致；但 V5 侧栏的两项操作能力（分组折叠、整体折叠/拖拽）在 V6 里消失了。

参考站

侧栏 29 分类平铺，每项 18×18 线性图标 + 标签 + 计数胶囊，激活项主色实底。固定 228px，不可折叠。

干净、可预期、视觉统一 29 项长列表在矮屏需滚动；无法为内容区腾空间

V5

侧栏 240px，可折叠成 60px 纯图标态，可拖拽调宽 160–400px；分类按域分组且可折叠（category-group + chevron）；导航项带收藏/回收站角标。

分组折叠解决长列表；折叠/拖拽让用户掌控空间；角标给出未处理数量 默认 240px 与参考站 228px 不一致；平铺式视觉不如参考站精致

V6

228px 吸顶侧栏 + lucide 图标 + 计数胶囊 + 底部卡片组，规格对齐参考站；但固定宽度、29 项平铺、无角标。

默认值对齐、视觉精致、底部卡片组给出控制台与说明入口 丧失折叠与拖拽；丧失分组；收藏/回收站数量只在顶栏更多菜单里
融合动作：保留 228px 默认与视觉规格（参考站），把 V5 的折叠（60px 图标态）+ 拖拽调宽（160–400px）装回，宽度用 versionedPersist 持久化；分类默认平铺（对齐参考站），额外提供「按域分组」开关。

4.3 卡片形态与毛玻璃取舍

采用 V6

形态已完全对齐，唯一待议的是参考站有、V6 主动去掉的逐卡毛玻璃。

参考站

18px 圆角 / min-height:154px / blur(22px) saturate(190%)；悬停 translateY(-3px) scale(1.004) + 主色描边环；≤800px 转 iOS 列表行（图标 56、动作区 74、分隔线左起 68px）。

视觉层次与质感是三方最强 301 张卡同时开毛玻璃会拖垮滚动

V5

实色白底、12px 圆角、--shadow-card 极浅；网格/列表由 viewMode 切换，非断点驱动。

渲染廉价，滚动无压力 质感明显落后；两态切换靠手动而非自适应

V6

完整复刻参考站桌面与移动两套形态；按性能取舍移除了逐卡 backdrop-filter，保留半透明底与阴影。

形态对齐且滚动 60fps；移动列表行分隔线左起 68px 已复现 玻璃质感略弱于参考站
融合动作：形态不动。毛玻璃条件启用——仅在 ≥1181px 且可见卡片数低于阈值时开启，或只对悬停卡开启，兼顾质感与帧率。

4.4 详情呈现：V6 丢了「零点击查看」

V6 路由 + 回收 V5 悬停

这是 V5 最被低估的一处设计：鼠标划过即出详情，不需要点击、不打断浏览节奏。

参考站

独立详情路由 /apps/<slug>，详情页图标放大到 152×152、圆角 33px。信息架构清晰、可分享、可被收录。

可分享、可索引、移动端体验好 必须离开列表，浏览节奏被打断

V5

右栏 280px 常驻面板，悬停卡片即渲染：图标 + 分类标签 + 简介 + 使用统计（访问次数 / 已添加 / 上次访问）+ 时间线 + 打开/复制/收藏三个操作。

零点击、零跳转；三栏并置适合快速横向比较 占 280px 固定宽度；无独立 URL，无法分享到具体站点；移动端无法承载

V6

路由页 /site/:id，含探活状态标签、简介、使用统计、时间线；图标 88×88 / 圆角 24。

可分享、有 URL、含健康状态（参考站没有） 回到列表才能继续看下一个；图标规格未对齐参考站的 152×152
融合动作：路由页作为「深入」入口保留并把图标对齐到 152×152 / 圆角 33；同时在 ≥1181px 增加悬停预览浮层（默认不占位、不改变网格），把 V5 的零点击查看以「轻量 popover」形式找回。

4.5 搜索：位置用 V6，能力补 V5

V6 位置 + 回收 V5 建议

V6 把搜索放进了顶栏（对），但把 V5 的建议下拉整段砍掉了（可惜）。

参考站

顶栏一个搜索框，h34、圆角 10、宽度 clamp(150px,22vw,320px)，带 ⌘K 提示；无建议下拉。

位置正确、克制 只有结果过滤，没有「输入即导航」

V5

SiteSearchBar：300ms 防抖、最多 6 条建议、关键词 <mark> 高亮、分类标签、直达链接、↑↓ 选择 + 回车打开、结果计数、Ctrl+F 聚焦。

键盘可全程操作，输入即可直达站点 占独立一行、把首屏往下推；高亮用 v-html 注入，有 XSS 风险（见 §06）

V6

抽出通用 SearchField 放进顶栏，含放大镜、清除按钮、⌘K 提示、移动端 16px 防缩放；但无建议下拉。

位置与形态对齐参考站，组件可复用 丢了建议、高亮、键盘选择与直达能力
融合动作：保持顶栏位置与外观，把 V5 的建议下拉移植进 SearchField（图标 + 名称/描述高亮 + 分类标签 + 直达 + ↑↓/回车）；高亮改用 DOM 分段渲染，不再走 v-html。

4.6 筛选层

采用 V6

参考站维度更多，但 V6 的「可分享筛选态」是参考站没有的。

参考站

五维：类型 / 平台 / 内核 / 代码 / 价格，另有已选条件 chips 与空结果重置入口。

维度最丰富 筛选态不进 URL，刷新即丢

V5

仅分类 + 关键词 + 排序 + 视图切换，没有独立筛选层。

简单 无法按状态/收藏快速收敛

V6

分类 chips + 仅收藏 + 健康状态（在线/限流/无法访问）+ 结果计数 + 排序 + 视图切换 + 已选 chips；全部写入 URL query，可分享、可前进后退。

筛选态可分享、可回退；健康筛选会触发整体探活 缺参考站的「平台」维度（需先补站点数据字段）
融合动作：采用 V6。平台维度列为 P2 —— 需先给站点数据补 platforms 字段，属于数据层工作，不阻塞本轮。

4.7 统计条与小组件：一半被弱化，一半成了死代码

部分回收 + 清理

V5 的首屏信息很丰富（统计 + 时钟 + 天气 + Google 搜索），V6 为对齐参考站的「紧凑首屏」把它们压缩了 —— 但压缩得不彻底，留下了孤立组件。

参考站

首屏只有顶栏 + 筛选 + 卡片，没有统计条与小组件。

首屏紧凑，卡片是唯一主角 没有任何全局计数

V5

StatsBar 常驻首屏：共 N 个站点 / 今日访问 / 收藏，右侧排序下拉 + 网格/列表 + 主题 + 设置。另有 DigitalClock、WeatherWidget、GoogleSearchBar。

一眼掌握全局与今日活跃度 四行内容把卡片推到首屏之外

V6

排序/视图进了 FilterBar，主题进了顶栏，设置进了顶栏「更多」菜单，时钟进了 SiteFooter；GoogleSearchBar 与 WeatherWidget 已零引用，ThemePicker 同样零引用。

首屏回归紧凑，各归其位 「今日访问 / 收藏」统计丢失；三个组件挂在仓库里没人用
融合动作：把「今日访问 / 收藏」补到页脚或侧栏底部（轻量、不占首屏）；删除 GoogleSearchBar、WeatherWidget 两个零引用组件；ThemePicker 的去留由下一节决定。

4.8 主题能力：多预设换肤被丢下

回收 V5

V5 有「主题换肤」面板，V6 只剩浅/深二态，而 ThemePicker.vue 还在仓库里。

参考站

浅/深两套完整 token（:root 与 .dark），组件只引变量、不写字面色值。

体系干净，双主题一致性好 只有两态

V5

浅/深 + ThemePicker 多预设（preferencesStore.themePreset），可整体换肤。

个性化更强 预设色值散落，未收敛到 token

V6

token 层已按参考站口径重建（tokens.css），浅/深完整；ThemePicker 已无引用。

token 体系是三方最规范的 多预设能力丢失
融合动作：把 ThemePicker 接回设置面板（入口已在顶栏「更多 → 设置」）；预设需映射到 V6 的 token（只覆盖 --primary / 光晕 / 强调色，不动结构 token），避免破坏与参考站的对齐。

4.9 移动端导航与一处未对齐的规格

V6 基底 + 补规格

V6 用底部 tab 栏替换了 V5 的顶部抽屉（对），但高度比参考站矮了 12px。

参考站

.mobile-site-tabs：z-index:40、高 calc(72px + safe-area-bottom)、内边距 6px max(10px, safe)；body 预留 80px + safe。

触控区充裕，与安全区配合完善 —

V5

顶部 MobileHeader 汉堡 + .overlay 抽屉；侧栏 transform 滑出。

侧栏内容可直接复用桌面版 顶部占位、抽屉打断浏览；无底部触达

V6

MobileTabBar：4 个 tab（发现/分类/收藏/设置）、z-index:40、高 calc(60px + safe-area-bottom)，收藏带角标。

形态正确、含角标、设置入口合理 高度 60px ≠ 参考站 72px；catalog 底部预留 96px 与参考站 body 80px 口径不同
融合动作：tab 栏高度改为 calc(72px + safe-area-inset-bottom)，内边距对齐 6px max(10px, safe)；同步复核 catalog 底部预留，避免内容被遮挡或留白过多。

4.10 个性化与数据能力

采用 V6（本地独有优势）

这一层参考站完全没有，是本地项目的护城河，融合时只准加强、不准削弱。

参考站

无。纯展示型目录，无用户状态。

— 无法收藏、无法记录历史、无个性化

V5

收藏 / 待办 / 历史 / 回收站 / 批量选择 / 拖拽排序 / 命令面板 / 壁纸 / 云端会话同步 / 在线探活。

05

对齐残留项（本轮回归新发现）

这些是 V6 声称「已对齐参考站」、但实测仍有差距的地方。已回查参考站缓存 CSS 复核。

GAP-1

移动端底部 tab 栏高度差 12px

参考站 .mobile-site-tabs { height: calc(72px + env(safe-area-inset-bottom,0px)) }；V6 MobileTabBar 为 calc(60px + env(safe-area-inset-bottom))。

判定：实现与自身方案文档 §1.5 的「72px」口径不符，属实现残留。改动会联动 catalog 底部预留，需一并回归。
GAP-2

底部预留口径不一致

参考站用 body:has(.mobile-site-tabs){padding-bottom:calc(80px + safe)}；V6 在 catalog 上留 96px（M8 回归实测 catalog.pad = 0 18 96 18）。

判定：机制与数值都不同。当前效果可接受（96 > 80 有余量），但应统一为单一来源，避免 tab 高度改动后出现遮挡或过大留白。
GAP-3

详情页图标规格未对齐

参考站详情页图标 152×152、圆角 33px；V6 SiteDetailView 为 88×88、圆角 24px。

判定：参考站把详情页当作「站点主页」来排版，图标是视觉主角；V6 偏保守。属可选对齐项。
GAP-4

三处零引用组件（死代码）

GoogleSearchBar.vue、WeatherWidget.vue、ThemePicker.vue 在 V6 中 import 引用数均为 0。

判定：前两个建议删除；ThemePicker 若按 §4.8 接回则保留，否则一并删除。

融合方案

按「先补规格、再回收能力、最后做增强」排序。P0 是必须做的收口，P1 是找回 V5 的核心体验，P2 是可选增强。

F1

移动端 tab 栏对齐 72px，统一底部预留口径

高度改 calc(72px + safe)、内边距 6px max(10px, safe)；把底部预留收敛到单一来源（body 或 catalog 二选一）。

依据：GAP-1 / GAP-2，参考站缓存 CSS 实测值。
工作量 · 风险低
F2

清理零引用组件

删除 GoogleSearchBar.vue、WeatherWidget.vue；ThemePicker 按 F6 结论决定去留。

依据：GAP-4，引用计数为 0。
工作量 · 风险低

收藏 / 待办 / 历史 / 回收站 / 批量选择 / 拖拽排序 / 命令面板 / 管理后台，逐项确认在融合改动后仍可用。

依据：方案文档 §三 第 7 条验收标准。
工作量 · 风险低
P1 · 回收 V5 能力本轮的核心价值，找回被误删的体验
F4

顶栏搜索建议下拉（移植 V5，修掉 XSS）

在 SearchField 内加建议层：图标 + 名称/描述高亮 + 分类标签 + 直达链接 + ↑↓ 选择 + 回车打开 + 结果计数；保留 300ms 防抖。

07

风险与注意事项

F4 搜索高亮必须重写，不能照抄。V5 用 v-html 注入 <mark>，虽然对搜索词做了正则转义，但一旦站点名/描述中含 HTML，注入面仍然存在。移植时必须改为 DOM 分段渲染。
F7 与参考站的信息架构存在张力。参考站明确用独立路由承载详情（不用侧滑面板）。加悬停浮层等于「多一种交互」，需确认这是可接受的增强，而不是对对齐目标的偏离。
F1 会联动三处。tab 栏高度改动会同时影响 catalog 底部预留、body 滚动留白、以及内容末尾是否被遮挡，必须一起回归七宽度。
F5 / F6 必须做移动端隔离。折叠态与拖拽手柄只在桌面生效；≤800px 侧栏整体 display:none，不要因为加回折叠而破坏移动端形态。
对齐基线已有自动化。七宽度回归脚本（_tmp-align-regress.mjs）可复用；建议把 F1/F5/F7 的改动都纳入同一套回归，避免再次出现 GAP-1 这类「声称对齐但实测不符」的情况。
数据层能力不要动。本地覆盖层、会话同步、探活分级、URL 状态同步是三方对比中唯一的「护城河」，融合改动一律以不破坏它们为前提。
