| 维度 | 现在有什么 | 关键缺口 |
|---|---|---|
| 可视化 | 8 套视觉方案 + 21 个令牌；卡片三档密度；三态健康角标；热度徽章；rich 档封面 | **零图表**（无 echarts/d3/chart.js）；唯一的"图"是后台手写 CSS 条；**前台没有洞察视图**；点击只有累计数、无时间维度；体检只存快照、无趋势 |

## 1. 可视化

### V1 · 洞察面板（P0，v11 门面）

新增路由 `/insights`（postbuild 会自动生成目录入口，SPA 兜底不用操心），异步加载，前台与后台共用一套图表原语。

- **三块内容**：① 使用热度 TOP10（带 sparkline）② 分类分布（环形 + 条形）③ 站点健康度（环形 + 异常清单直达）
- **图表原语 `src/utils/chartkit.js`**：只做 4 个纯函数（sparkline / bar / donut / heatstrip），输入数据 + 尺寸，输出 SVG 字符串。**零依赖、无运行时开销、SSR 友好**。
- 入口：侧栏加「洞察」项 + 命令面板 `page` 组补一条 + 首页右上角可选小入口。
- 验收：`/insights` 直达与刷新均正常（SPA 兜底脚本覆盖）；空数据有空态而不是空白画布。

### V2 · 点击计数加时间维度（P0，V1 的数据地基）

`shared/clicks-core.mjs` 当前只有 `{id: count}`，sparkline 无从谈起。

- 结构扩展为 `{ total, buckets: { 'YYYY-MM-DD': n } }`，**保留旧结构读兼容**（缺 buckets 即视为 total 全在"未知日期"），不破坏既有 `rankByClicks`。
- 落库时滚动裁剪（保留 90 天），`api/clicks.js` 写入侧同步。
- 验收：test-clicks 新增"旧结构可读 / 新结构可写 / 裁剪不越界"三条；真机点两次卡片，洞察面板 sparkline 出点。

### V3 · 健康趋势留存（P1）

- `health` 落库追加 `history`（滚动保留最近 12 次判定），产出 `recovered` / `degraded` 事件。
- 卡片 tooltip 增补「连续 N 次异常 / 上次恢复于 X」；洞察面板出"健康度变化"。
- 约束：巡检是**请求驱动分片跑**的（沙箱无长驻进程），history 只在判定实际发生时追加，不得为"凑趋势"制造额外出网。

### V4 · 图表视觉令牌（P1）

- 新增 `panel:'chart'` 分组（配色/网格/圆角/是否显示数值），**颜色仍然只取语义 token**，不硬编码、不进卡片面板。
- 加令牌必须给 8 套方案全部补值，`test-visual-scheme` 的 CSS 变量快照同步补，否则守卫红。

### V5 · 封面命中率兜底（P1，低成本高收益）

现状 12 站只有 1 站拿到 og:image（多数站是 SPA 或沙箱不可达），rich 档大量空白。

- 204 时不再简单摘图层，改为 **`hashColor(domain)` 生成的双色渐变占位 + 站点首字**（`shared/hash-color.mjs` 现成，零新增依赖）。
- 视觉上从"缺一块"变成"有意设计"，且和卡片配色体系同源。

### V6 · 主题分享（P2）

- `exportThemes/importThemes` 已存在，补「复制链接导入」（主题 JSON 编码进 URL hash，`/theme#<base64>` 落地即应用，需用户确认再写入）。
- 注意：主题存的是"覆盖"而非快照，导入时按同样语义合并，别整份替换。

## 2. 智能化

### I1 · 点击回流搜索排序（P0）

现在的搜索只有相关性分档，同档内按固定 tieBreak，用户点哪个站不影响下次排序。

- 在 `search.js` 的**同档位内**叠加 `clickBoost = log(1+count)` + 最近访问时间衰减，权重小（保证相关性不被压过），**可解释**（OmniBox 结果可标"常访问"）。
- 开关进 `preferences`（默认开），保守可回退。
- 验收：test-search 新增"同档位下高点击站排前 / 关掉后恢复原序"。

### I2 · 搜索历史与补全建议（P1）

- localStorage 存最近 20 条查询（走 `safeStorage.js`，不进 session 同步以免污染跨设备）。
- OmniBox **空态**显示「最近搜索 / 常用站点」；输入时做前缀补全建议（复用既有分档评分，不新建引擎）。
- 提供清除入口，命令面板补一条「清除搜索历史」。

### I3 · 自然语言进命令面板（P1，接线活）

`utils/intent.js` 已有规则解析，但**命令面板完全没用它**。

- OmniBox 无前缀输入时：先过 intent，置信度够高 → 当作命令执行（显示"理解为：切换到深色"并可 Esc 撤销）；否则走搜索。
- 约束：intent 是规则不是模型，只覆盖"切换到 X / 打开 X / 把 X 归到 Y"这类，别承诺听不懂的。
- 验收：test-intent 扩到"命令面板解析路径"，误命中要能一键退回搜索。

### I4 · 推荐加负反馈（P1）

- SmartBar 每张卡补「不感兴趣」：写入 session（**不进站点表**），smartRank 读该集合降权。
- 时段切分目前写死 4 段，样本足够时（≥50 次访问）按实际分布做简单聚类自适应；样本不足维持现状。

### I5 · AI 平民化（P0，含一处既有缺陷修复）

**缺陷**：`AddSiteModal.vue` 的「AI 润色」按钮请求带 `getAdminKey()`，普通用户没有 key → 必失败，且失败文案看不出原因。

- 修法：新增**只读润色端点**（服务端配置存在即可用，按 IP 限流，不做写操作），与需要 admin key 的 categorize/summarize 分开鉴权。
- 未配置 AI 时按钮**隐藏**（沿用现有"未配置即隐藏入口"约定），而不是点了报错。
- 不越界：AI 输出仍需用户确认才落库（v10 已定的设计，别改成自动写）。

### I6 · 体检维度扩展（P2）

- 现状只判 HTTP 状态码，`ms` 记录了但不分级。补：时延分级（>3s 标 limited）、内容 hash 变化检测（发现"页面变样"，可能是站点改版或被墙）。
- 约束：沙箱处理超几秒的请求会在响应前被回收 → 必须秒级超时 + 负缓存，不然表现为偶发失败。

### I7 · 智能去重（P2）

300 站里大概率存在同站多 URL（www/非 www、http/https、主域与子域）。

- 离线扫描产出"疑似重复"清单，**只建议不自动合并**，后台审阅后一键处理。
- 复用 `sanitize` 与 `hostOf`，不新造判定。

## 3. 体验优化

### E1 · 卡片网格键盘导航（P0，最大缺口）

86 处 aria 却没有键盘导航，键盘用户只能用 Tab 一张张跳 300 次。

- **roving tabindex**：网格容器 `role="grid"`，只有一张卡 `tabindex="0"`，方向键移动焦点（←→ ±1，↑↓ ±列数，Home/End 到首尾）；列数从实际布局读（masonry 多栏下退化为线性）。
- Enter/Space 打开（复用既有 `openSite()`），`/` 聚焦搜索，`Esc` 回到网格。
- 验收：新增 test-gridnav（纯函数算"下一张是谁"），真机 CDP 发方向键断言焦点 id 变化。

### E2 · 浮层无障碍补完（P0）

- CommandPalette / ShortcutsPanel / AddSiteModal / EditSiteModal：`role="dialog"` + `aria-modal` + **焦点陷阱** + 关闭后**焦点归还**触发元素。
- 批量复选框现在是 `div`，改 `input[type=checkbox]`（键盘可达）。
- 网格容器补 `role="list"` 语义；批量操作结果用 `aria-live` 播报（"已移动 12 个站点到 AI 工具"）。

### E3 · 移动端（P1）

- **拖拽替代**：移动端进入排序模式后给「上移 / 下移 / 移到最前 / 移到分类…」按钮（不碰 vuedraggable，触摸端本就不可用）。
- `MobileHeader` 补搜索入口（现在只有汉堡 + 标题，搜索挤在工具栏竖排）。
- 便签墙在移动端未做专项适配，至少保证不溢出、可关闭。

### E4 · 批量操作补全（P1）

- 现有：全选/取消/改分类/加用途/删除（进回收站）。补：**置顶、归档、反选**。
- **批量撤销**：现在是单条 `undoAdd`。做轻量操作栈（存 session，只保留最近 10 步的反向操作），批量删/改后 5 秒内可撤销。
- 约束：不加"框选"（与 masonry 的 CSS 多栏冲突），保持逐张点选。

### E5 · 虚拟滚动（P2，先别急）

300 卡在 `content-visibility:auto` 下已够用，且 masonry 用 CSS 多栏**根本无法虚拟**。

- 若要做，只对 fixed/auto 档做窗口化，masonry 保持现状。
- 触发条件：卡片数增长到 600+ 或滚动实测掉帧再上。

### E6 · 同步状态可视化（P1）

session 同步现在是静默合并式回填，用户不知道同步了没、有没有冲突。

- 侧栏/设置里补「上次同步时间 / 冲突 N 项 / 手动推送拉取」，冲突项列出来让人选（现在合并式会静默取舍）。
- 不动 `liveSync.js` 的"只推两字段"策略，那是防覆盖的刻意设计。

### E7 · 回收站与归档管理（P2）

- 有 `/archived` 路由与回收站，但缺**批量恢复、清空二次确认、站内搜索**。
- 批量恢复可复用 E4 的批量框架，成本很低。

## 5. 不变量（v11 期间不可破）

1. **首屏预算 600/230 不放宽**：图表手写 SVG，洞察面板等一律异步/独立路由。加完必跑 `console:test:bundle`。
2. **颜色只许语义 token**：图表配色也不例外，新增 `panel:'chart'` 令牌要给 8 套方案补满并同步 `test-visual-scheme` 快照。
3. **AI 不直接改数据**：输出必须用户确认后落库（v10 已定）。
4. **备注/便签/负反馈不进站点表**：走 session（`SYNC_FIELDS` 白名单），公共数据会被发布冲掉。
5. **合并逻辑单一实现**：健康判定继续只在 `buildHealthPayload`，趋势只是追加记录，不复制第二份判定。
6. **沙箱无长驻进程 / 请求会被回收**：任何出网改动（I6）必须秒级超时 + 负缓存。
7. **改弹窗状态文案同步 test-bundle 的 LAZY_PARTS 标记**。
8. **新增路由自动获得 SPA 兜底**（postbuild 提取），但发布后仍要跑 `probe/verify-static-standalone.mjs` 验证直达与刷新。

## 6. 验收口径

- `npm run console:test:all` 全绿（新增套件并入 `test:all`）+ `npm run validate`。
- 首屏体积不超 600/230（`console:test:bundle`，缺产物用 `--strict`）。
- 真机：`probe/v8-verify-ui.mjs`（29 项）不回归；`/insights` 走 `probe/verify-static-standalone.mjs` 验直达与刷新。
- 键盘：纯键盘完成「聚焦搜索 → 方向键选卡 → 打开 → 关浮层焦点归还」全链路。
