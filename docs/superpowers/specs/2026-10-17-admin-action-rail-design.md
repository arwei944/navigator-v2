# 管理后台 · 左动作栏 + 侧栏自由宽度 —— 设计文档

日期：2026-10-17
范围：管理后台中间区（`src/views/AdminView.vue`）+ 主站两侧栏（`Sidebar.vue` / `RightSidebar.vue` / `stores/sidebar.js` / `utils/sideWidth.js`）
决策来源：用户在五款可交互原型（`docs/admin-layout-lab-v2.html`）里选了 **② 左动作栏**，
同时要求 **侧栏可以自由折叠、改变宽度**。

---

## 0. 需求

用户在体验页上给出的两条原话：

1. **「没有层次感和突出重点」** —— 上一版是一屏 12 张等大的模块卡片：**全是重点 = 没有重点**。
2. **「模块之间的切换次数太多」** —— 上一版「返回 → 点卡片 → 再点里面的按钮」= 3 次。

补充要求：侧栏能自由折叠与改宽度。

## 1. 上一版为什么被否（记下来避免再犯）

| 上一版 | 问题 |
|---|---|
| 卡片仪表盘（12 张等大卡） | 面积、字号全都一样 → 没有主次；12 个模块状态平铺，读者要自己找重点 |
| 面包屑导航 | 进模块要「返回 → 点卡片」= 2 次；模块内的动作还要再点 = 3 次 |

## 2. 方案

### 2.1 左动作栏：栏里列「能做的事」，不列「模块」

三组，**组本身就是层次**：

| 组 | 内容 |
|---|---|
| 常用动作 | 发布到云端 · 检查更新 · 导出备份 · 巡检结果 |
| 批量 | 批量刷新描述 · AI 生成描述 |
| 模块 | 概览 · 站点管理 · 分类体系 · 部署 · 插件 · 快照与回滚 · 发布历史 · 操作审计 · 通知中心 · 偏好设置 · 备份与恢复 |

**模块的实时状态写在栏内右侧**（`站点管理 300`、`插件 9`、`操作审计 10`、`部署 8eb59ad`…）——
这正是「12 张等大卡片」可以被删掉的原因：状态不再需要占一整屏。
概览因此回到「KPI + 数据洞察」，是一个有主次的页面，而不是一屏等大卡片。

### 2.2 「一次点击」的边界：只读动作点一下即执行，危险动作**刻意要两次**

这条是刻意的设计，不是没做完：

| 动作 | 点击数 | 为什么 |
|---|---|---|
| 切到任意模块 / 动作 | **1** | 点栏内项即达 —— 用户诉求的主项 |
| 检查更新 | **1** | 只读，点一下就把结果摆出来 |
| 导出备份 | **1** | 点一下即开始下载（并回显体积） |
| 巡检结果 | **1** | 只读快照 |
| **发布到云端 / 回滚 / 恢复备份** | **2** | **不可逆动作不绑在导航点击上**：误触一次就是线上事故。仍走「进入面板 → 再点执行」 |
| 批量刷新描述 / AI 生成描述 | 1 + 选站点 | 这两个动作本身需要「对哪些站点」，参数不可省 |

### 2.3 栏自身可折叠、可拖宽

- 折叠态 56px 只留图标；展开态可拖 56–340px；**双击把手复位**到 224px；
- 宽度与折叠态存本机（`nav_admin_rail_w` / `nav_admin_rail_collapsed`）。

### 2.4 主站两侧栏：宽度自由化

原来两侧栏已经是 60–400 可拖 + 可折叠，这次把它做「更自由」：

| 改动 | 说明 |
|---|---|
| 范围 60 → **520** | 侧栏里最长的是站点名，520 能整行放下；下限 60 是**图标的物理下限**（导航项 44 + 左右各 8），再窄就只剩一条空栏 |
| 左栏**折叠态也能拖** | 原来折叠后没有把手，得先按展开按钮；现在从图标栏直接往外拖就展开 |
| **双击把手复位** | 拖宽之后一键回到出厂宽度（左 240 / 右 280） |
| 范围与钳制抽成纯函数 | `utils/sideWidth.js`，两侧栏共用一套，改一处即可 |

**空值不按 0 处理**：`Number(null)` 是 0，会一路钳到下限 —— 于是「持久化数据坏了」的表现是
**侧栏悄悄塌成图标栏**，用户会以为布局坏了。现在空值回落默认宽度。

## 3. 验收

| 项 | 方式 | 结果 |
|---|---|---|
| 宽度契约（范围 / 空值 / 下限 / 图标阈值） | `tools/console/test-side-width.mjs` | **22 条** |
| 动作栏与侧栏的真实行为 | `probe/admin-shell-verify.mjs`（真机，本地 + 线上） | **30 条** |
| 全量回归 | `console:test:all` | 62 个脚本 |

真机覆盖：栏内三组 + 17 项 + 13 项带状态数字 / 点一下切模块（且内容真的换了）/ 点一下执行动作
（巡检返回 正常·可忽略·需处理；检查更新返回 线上版本·构建状态·与上游对比）/ 折叠到 56px 且标签不渲染 /
拖宽 / 往左狂拖被钳在下限 / 双击复位 224 / 左栏拖到 360 与上限 520、下限 60 / 双击复位 240 /
右栏拖到 380 与复位 280 / 无控制台错误。

## 4. 过程中踩的坑（值得记）

**一次静默失败的替换**：我脚本化地把 `import ... from '@/utils/tabOverflow'` 那行替换成新导入，
但那行**在更早一轮就已经被删掉**了 —— 替换什么都没做，也没报错。结果：
`clampRailWidth` / `fetchDeployStatus` 全是未定义标识符，**整个 AdminView chunk 加载失败**，
页面中栏一片空白，而且 console 里干干净净（模块链接期错误不会被组件捕获）。
现象是「探针进不去后台」，诊断办法是让探针把页面文本打出来 —— 一眼看到中栏是空的。
**教训：脚本化替换以后要核验"替换后的那一行真的在"**，不是只 grep 用法。

## 5. 不做的事

- **不把危险动作用一次点击**（见 2.2，安全优先）；
- **不给动作栏加拖拽排序**：组的顺序是设计的一部分，不是用户偏好；
- **不改 13 个面板的内部布局**：本次只动中间区的组织方式与两侧栏宽度。
