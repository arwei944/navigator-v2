# 全能框（OmniBox）设计

**日期**：2026-10-10
**状态**：已实现
**范围**：把顶部搜索框升级为「一个输入框完成站内一切操作」的智能框，并吃掉现有命令面板。

---

## 1. 目标

用户诉求：「把搜索框升级为全能框，可以进行一切操作，做成一个智能框。」

翻译成验收口径：**顶部那个输入框，是这个导航站唯一的万能入口**——找站点、开站点、管站点、切状态、跳页面，全部在一个框里完成，且中文/拼音/别名/模糊都能搜到。

### 非目标（明确排除）

| 排除项 | 理由 |
| --- | --- |
| 计算器、翻译、单位换算等通用工具 | 「一切操作」指**站内**操作。塞通用工具会让全能框变成四不像，且挤占站点结果的权重 |
| 第三方库（cmdk / kbar） | 项目已有检索内核，自写 200 行即可，无谓增依赖 |
| 命令结果写回网格过滤 | 执行一条命令不应清空页面，见 §5.3 |

---

## 2. 现状诊断

| 现状 | 问题 |
| --- | --- |
| `UnifiedSearchBox.vue`（顶部搜索框） | 只搜站点 + 站外搜索出口；右上角 `⌘K` 按钮用 **伪造 `KeyboardEvent`** 去开命令面板 |
| `CommandPalette.vue`（Ctrl+K，5 组） | 页面/方向/分类/站点/操作都在，但**操作只有 2 条**；除站点组外其余四组只用 `String.includes`——「主题」打 `zhuti` / `zh` 搜不到 |
| `src/utils/search.js` | 已有 14 档评分 + 拼音 + Fuse 模糊 + 高亮，注释明写「页面搜索框与命令面板共用」→ **可零改动复用** |
| 两个入口的关系 | 完全割裂：搜索框不知道命令的存在，命令面板不知道当前搜索词 |

### 三个必须修的结构性缺陷

1. **`/admin` 下 Ctrl+K 完全无效** —— `App.vue` 用 `v-if="isStandalone"` 跳过整个布局（含命令面板）。
2. **编辑 / 删除命令够不着** —— 这两个弹窗挂在 `CardsContainer` 内层、由卡片 `emit` 触发，命令层拿不到。
3. **`ShortcutsPanel` 写了 `Ctrl+D 切换主题` 但全仓无绑定** —— 文档承诺了却没实现的死条目。

---

## 3. 架构决策

### 3.1 一个内核，两个外壳（核心决策）

不做「把命令面板删掉全塞进搜索框」，也不做「保留两套」。而是：

```
                 ┌──────────────────────────────┐
                 │  useOmniBox.js（状态机）      │
                 │  查询解析 / 分组 / 页面栈 /导航 │
                 └──────────────┬───────────────┘
                                │ 共用
              ┌─────────────────┴─────────────────┐
              │                                   │
   UnifiedSearchBox.vue              CommandPalette.vue
   （inline 外壳：工具栏下方下拉）      （palette 外壳：居中浮层）
   日常搜索，输入即过滤网格             Ctrl+K 命令执行，不动网格
```

**理由**：两个入口的用户心智不同（搜索框偏「找东西」，Ctrl+K 偏「干活」），但底层命令、检索、评分必须是同一套，否则又会出现「同一关键词两处结果不同」。共用 `useOmniBox` 后两者天然一致。

### 3.2 命令注册表

`src/utils/commands.js` 导出 `buildCommands(ctx)` —— 纯函数，接收宿主注入的回调，返回命令数组。命令不直接 import store，避免与组件生命周期纠缠。

```js
{
  id: 'theme.toggle',
  title: '切换主题',
  subtitle: '在浅色与深色之间切换',
  section: 'view',          // 分组：goto / view / action / site
  icon: 'sun',
  keywords: ['zhuti', 'zt', 'theme', 'dark', 'qiehuanzhuti'],
  run: () => ctx.toggleTheme()
}
```

`keywords` 手写中文拼音是必要的——「切换主题」的自动拼音是 `qiehuanthemetoggle` 之类，用户输入 `zt` / `zhuti` 都该命中。

### 3.3 全局动作宿主

新建 `src/stores/omni.js`：

```js
editTarget    // 请求编辑某站点
deleteTarget  // 请求删除某站点
addPrefillUrl // 请求以某网址打开添加弹窗
```

命令只 `omniStore.requestEdit(site)`，由 `App.vue` 监听并渲染 `EditSiteModal` / `ConfirmDialog` / `AddSiteModal`。**命令层不持有 DOM 状态**，耦合最松，也顺带解决了「编辑/删除命令够不着」的缺陷。

### 3.4 检索打分统一

在 `src/utils/search.js` 新增并导出通用文本打分：

```js
scoreText(text, q)   // 单个文本：精确 > 前缀 > 包含 > 拼音全拼前缀 > 拼音首字母前缀 > 拼音包含
matchAny(list, q)    // 关键词数组取最高分
```

命令 / 页面 / 分类 / 用途全部走它，**与站点共用 pinyin-pro 与同一套档位序**，从此 `zhuti`、`zt` 都能搜到命令。

## 4. 输入语法

| 输入 | 语义 |
| --- | --- |
| `chat` | **默认**：命令 + 页面 + 分类 + 站点混合，按相关度排序后智能分组 |
| `>pin` | `>` 只搜命令 |
| `@chat` | `@` 只搜站点 |
| `/recent` | `/` 只跳页面 |
| `github.com` | 像网址 → 一键收录（优先于站外搜索，沿用既有决策链） |

**页面栈（二级页）**：选中站点后按 `Tab`（或输入 `>`）进入该站点的操作页——打开 / 新窗口打开 / 复制链接 / 查看详情 / 收藏 / 置顶 / 归档 / 编辑 / 删除。`Esc` 或退格回上级。

采用「对象在前」而非「命令在前」（`>pin <站点>`），因为前者按键更少、不需要在命令和站点名之间切换心智。

## 5. 数据流与边界

### 5.1 结果分组顺序

```
命令 → 页面 → 方向 → 分类 → 站点 → 站外搜索出口
```

分组内按分数降序；组内分数相同时保持注册顺序（稳定）。

### 5.2 无输入时的默认视图

- inline 外壳：不展开（点击才展开，避免遮挡网格）
- palette 外壳（Ctrl+K）：**最近访问站点 + 常用命令**，打开即可用

### 5.3 与全局网格过滤的边界（关键）

| 外壳 | 输入是否过滤网格 | 理由 |
| --- | --- | --- |
| inline | **是**（沿用现有 300ms 防抖 → store → `?q=`） | 用户已习惯「边打边筛」，改掉是倒退 |
| palette | **否** | 命令执行不该清空页面 |

命令执行后：清空输入框、关闭浮层、恢复焦点。
