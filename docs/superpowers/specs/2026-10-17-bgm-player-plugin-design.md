## 0. 需求

「先新增一个**简约的音乐播放器插件**，播放背景音乐。」

## 1. 音源：程序合成，不是音频文件

| | 结论 |
|---|---|
| 为什么不用真歌文件 | 站点**公开可访问**，放有版权的歌＝公开传播；CC0 素材还要挑、要打包体积（每首 40–150 KB） |
| 为什么不用外链 | 版权 + CORS + 防盗链 + 依赖第三方可用性 |
| **选了程序合成** | 零素材、零版权、离线可用；代码本身就是曲子。听感是**环境音乐**（铺底 + 琶音 + 低音），正是「背景音乐」要的 |

三首内置曲目：黄昏（Am–F–C–G，56 BPM）／清晨（C–G–Am–F，66）／夜行（Dm–B♭–F–C，50）。

## 2. 分层

| 层 | 文件 | 职责 | 可测性 |
|---|---|---|---|
| 乐谱 | `utils/bgmScore.js` | 音高换算 / 和弦循环 / 一小节的音符事件 / 音量钳制 | **纯函数，104 条断言**（同小节必须每次生成一致，否则"每听一遍都在变"） |
| 播放 | `composables/useBgmPlayer.js` | Web Audio **单例**：懒创建上下文、提前排程、ramp 换曲 | 真机探针 |
| UI | `components/BgmPlayer.vue` | 右下角胶囊：播放/暂停 · 曲目 · 已播时长 · 上一首/下一首 · 音量 · 关闭 | 真机探针（**真实输入事件**） |
| 开关 | `components/settings/BgmSection.vue` | 开/关 · 选曲 · 音量 | —— |

**三条底线**（写在 composable 头部）：单例（多实例＝叠音）、懒创建（无手势的上下文只会是 suspended，白占资源）、换曲/暂停不爆音（增益全走 ramp，不直接赋值）。

## 3. 两个刻意的设计决定

### 3.1 单向数据流：偏好是唯一真源，播放器 watch 它

设置面板**只写偏好**，不直接操作播放器；播放器 `watch(prefs.bgmTrack / bgmVolume)` 跟随。
好处有二：不会出现「两处各存一份、谁覆盖谁说不清」；而且设置面板与播放器**不再共享模块**，Rollup 就不会把播放器并进设置面板那个 35 KiB 的大包 —— 实测拆开后 `BgmPlayer` 是独立的 **5.3 KiB** chunk。

### 3.2 首次交互后自动起，但跳过播放器自身的点击

浏览器禁止无手势出声，所以「背景音乐」只能是**第一次点击/按键之后**响起。
但有一个坑：如果那一下正好落在播放器自己的按钮上（比如用户直接点暂停），
自动起播与按钮语义会打架 —— 出现「先起后停」的闪烁。所以监听里显式排除 `.bgm` 内的目标。

## 4. 验收

| 项 | 方式 | 结果 |
|---|---|---|
| 乐谱内核（可复现 / 小节内 / 增益安全 / 三首曲目都成立） | `tools/console/test-bgm.mjs` | **104 条** |
| 真机（设置开关 / 挂载 / **真的出声** / 换曲 / 音量落盘 / 关闭卸载） | `probe/bgm-verify.mjs` | **18 条** |
| 首屏预算 | `test-bundle.mjs` | **613.8 ≤ 614 KiB**（只为一行异步声明付 0.6 KiB） |
| 首屏是否含音频代码 | 逐符号 grep | `createOscillator` / `AudioContext` / `noteFreq` **0 命中** |
| 无回归 | `console:test:all` | 63 个脚本 |

**「真的出声」怎么验**：用 **CDP 真实输入事件**点播放按钮（合成 click 不算用户手势，测出来会是"点了没反应"的假失败），
然后断言 `data-bgm=playing` 且**已播时长在走**（0s → 3s）—— 时长走起来说明音频时钟在跑。

## 5. 过程中踩的坑（这一轮最值钱的教训）

**脚本化替换连续三次静默失败**：我习惯用 node 一次性改多处，但锚点可能已被更早的改动删掉、
或格式对不上 —— 脚本不报错、只当没匹配到。这次其中一次导致 `watch` 没被导入，
BgmPlayer 的 setup 抛 `ReferenceError`，而**Vue 把组件错误吞掉**：页面上什么都不显示、也不影响其它渲染。

排查链路（记下来，下次直接走）：

1. 页面里没有播放器 → 先怀疑「异步加载失败」→ 直接在页面 `import()` 那个 chunk：**能加载**，排除；
2. 改成静态引入 → **仍不渲染** → 排除异步；
3. 去掉 `v-if` 无条件渲染 → **仍不渲染** → 排除条件，锁定组件自身；
4. 打印收集到的 console 错误 → 是**空串** → 检查收集器：它取 `args[0].value`，而 **Error 对象没有 `.value`**；
5. 改成取 `description` → **拿到真话**：`ReferenceError: watch is not defined at setup`。

→ **两条规矩**：① 脚本化替换后要核验「改后的那一行真的在」，别只 grep 用法；
② 探针的错误收集器要取 `description`，否则「空错误」会把排查带偏。

## 6. 不做的事

- **不把播放器绑到"点击卡片"上**：卡片点击现在是「打开站点」这个主流程，绑上去等于改语义（可行性调研里已说明）；
- **不做本地文件播放**（用户自带 mp3）：那是另一条路，需要文件选择与体积策略；
- **不做歌词/进度条/歌单**：这是「简约的」背景音乐，不是音乐 App；
- **不引入任何音频素材**：保持零版权风险。
