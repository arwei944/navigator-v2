# 管理后台模块导航升级 —— 设计文档

日期：2026-10-16
范围：管理后台中间区顶部模块导航（`src/views/AdminView.vue`）
决策来源：用户在 `docs/admin-layout-lab.html` 里选了 **L01 · 顶部标签（现状）**，要求「在这个基础上进行升级完善」

---

## 0. 需求

保留顶部标签这一形态（不换布局范式），把它**已知的两个代价**补掉。

## 1. 现状（改动前）

`.admin-tabs` 是一行 13 个平铺标签 + `overflow-x: auto`。两个代价是量化决策页里量出来的：

| 代价 | 实际情况 |
|---|---|
| ① 模块之间没有分组 | 13 个模块平铺，「发布相关」要在一条长线上从左扫到右 |
| ② 装不下的模块被滚出可视区 | 1440 屏下中间区只有约 900px（左右栏占掉 540px），**桌面端本来就有模块躲在滚动条外**；实测 1600 屏下 13 个标签需要约 1300px |

② 不是「窄屏才有的问题」——它在正常桌面分辨率下就成立，只是靠横向滚动把问题藏起来了。

## 2. 方案

骨架不动（还是顶部标签），补三件事：

### 2.1 分组

13 个模块分 5 组，并按「看 → 管 → 发 → 系统」重排：

| 组 | 模块 |
|---|---|
| 总览 | 概览 |
| 数据 | 站点管理 · 分类体系 |
| 运维 | 部署 · 插件 · 备份与恢复 |
| 发布 | 云端发布 · 快照与回滚 · 发布历史 |
| 系统 | 偏好设置 · 通知中心 · 操作审计 · AI 助手 |

- **横排**：一组的第一项左边留间距 + 一条细分隔线；
- **竖排**：不画分隔线，改插组标题（竖排本来就有分组的位置）。

重排是升级的一部分，不是顺手改的：分组必须对应一个连贯的顺序才有意义。
副作用：搜索索引的结果顺序会跟着变，快捷键（`g` 前缀）按 id 匹配，不受影响。

### 2.2 溢出「更多」

装不下的模块收进「更多」面板，而不是被滚出去。

- **可见区 = 顺序前 N 个 + 「更多」按钮**（不是把当前模块插到前面去）；
- **当前模块被收起时，「更多」按钮直接显示它的名字并高亮**（`⋯ 通知中心`）——
  否则用户切过去之后，导航里看不到自己在哪个模块，这是这个方案唯一的风险点，必须堵住；
- 面板里按原分组列出收起模块，与可见区保持同一套信息层级。

**宽度取容器而不是 nav 自身**：nav 会随「更多」按钮出现而变窄，拿它当基准会形成
「按钮出现 → nav 变窄 → 又少放一个 → 按钮文案变回去」的回路。
**「更多」按钮固定 104px**：文案在「更多 / ⋯ 当前模块名」之间切换，自适应宽度同样会抖动。

判断逻辑抽成纯函数 `src/utils/tabOverflow.js#computeVisibleCount`（26 条断言）——
这里算错不是变丑，是**模块从界面上消失**。

### 2.3 键盘可达

`role="tablist"` 配 roving tabindex：`←/→` 在可见模块间移动，`Home/End` 到首尾。
原来只能 Tab 逐个跳。

## 3. 配置

- 布局偏好 `nav_admin_layout`（横排 / 竖排）沿用，未新增；
- 分组表 `TAB_GROUPS` 与 `TABS[].group` 写在组件内（模块表本来就是这里的一处常量）；
- 无接口、无环境变量改动。

## 4. 验收

| 项 | 方式 | 结果 |
|---|---|---|
| 溢出计算（装得下 / 预留更多 / 极窄保底 / 脏数据 / 单调性 / 不改入参） | `tools/console/test-tab-overflow.mjs` | 26 条 |
| **装到 DOM 上真的成立** | `probe/admin-tabnav-verify.mjs`（真机） | 22 条 |
| 首屏预算 | `test-bundle.mjs` | 612.7 ≤ 614 KiB（导航在懒加载 chunk 里，不进首屏） |
| 无回归 | `console:test:all` | 61 个脚本 |

真机探针盯的是单测看不见的部分：**可见 + 收起 = 13 个模块一个不少**、
标签行没有被撑出横向滚动、面板按组列出、从面板切模块后 URL 与内容都对、
当前模块被收起时按钮显示它的名字且高亮、`←/→/Home/End` 真的动、
竖排显示 5 个组标题、420px 窄屏仍有入口、无控制台异常。

**探针自身修过一处判据**：最初断言「切到收起模块后，可见区里应有 `.active` 标签」——
这是错的。收起态的当前模块**本来就不该**在可见区有 active 标签，它由「更多」按钮代表示意。
改成取「有效当前模块」（可见区的 active，否则取按钮上的名字）。

## 5. 不做的事

- **不把当前模块强制挤进可见区**：那会让标签位置随选择跳动，比"知道自己在哪"代价更大；
  改用「更多」按钮承载指示。
- **不做标签自定义排序 / 隐藏**：那是用户偏好持久化，另一件事。
- **不改面板内部布局**：本次只动导航，13 个面板组件一行未改（这也是选 L01 的价值）。
- **不给「更多」面板加搜索**：13 个模块，面板里最坏也就列 3–4 个。
