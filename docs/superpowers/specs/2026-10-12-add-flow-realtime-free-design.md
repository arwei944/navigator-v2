# 站点添加全流程升级：抓取引擎 + 翻译引擎（实时 · 免费）

- 状态：**已实施**（2026-10-12）
- 日期：2026-10-12
- 目标（用户原话）：「站点添加的全流程进行升级改造，尤其是站点抓取引擎和翻译引擎，必须做到实时免费」
- 验收结果见 §2（含**未达成项**的如实记录）

## 1. 现状实测（先量后改）

### 1.1 线上 `/api/metadata` 端到端耗时

8 个真实站点，逐个打线上接口（2026-10-12）：

| 站点 | 总耗时 | 结果 |
|---|---|---|
| sspai.com | **844ms** | 成功（中文站） |
| vercel.com | 1697ms | 成功，desc 译成中文（mymemory） |
| stripe.com | 1790ms | 成功 |
| tapecode.ai | 2670ms | 成功，真实标题 |
| openai.com | 4485ms | 成功，desc 译成中文（mymemory） |
| news.ycombinator.com | 6366ms | ⚠ 抓取超时 → 域名推断 |
| figma.com | **10293ms** | 成功（Figma） |
| github.com | **13066ms** | ⚠ 抓取超时 → 域名推断 |

**中位数 ~3s，长尾 10~13s。** 用户感知的「不实时」全部落在长尾。

### 1.2 抓取层对照实验（本机，跟重定向，3 轮取中位数）

用项目自己的 `fetchCapped`，只换 header 与 `maxBytes`：

| 站点 | identity/256K（现状） | gzip/256K | **gzip/32K** | 提速 |
|---|---|---|---|---|
| vercel.com | 697ms | 381ms | **322ms** | 2.2× |
| figma.com | 1588ms | 1249ms | **1062ms** | 1.5× |
| openai.com | 1634ms | 1158ms | **661ms** | 2.5× |
| tapecode.ai | 357ms | 350ms | **57ms** | 6.3× |
| sspai.com | 293ms | 314ms | 327ms | ~1× |

**结论：主要杠杆是「早断」而不是「压缩」。** 读到 32KB 就断开，比读满 256KB 快 1.5~6 倍；压缩是次要收益（现代带宽下 TTFB 才是主导项）。

> 注：本机测不出 github.com（ECONNRESET/ETIMEDOUT），部署侧连得上但 6s 内没响应 —— **部署沙箱出网与本机网络不是同一条路径**，本机基准只能看相对关系。

### 1.3 「免费」这一侧的真实缺口

- **抓取**：我们自己的服务端，无外部配额 → 本来就免费。
- **翻译**：`shared/translate.mjs` 走 MyMemory（**免密钥，但额度按出口 IP 计的日配额**）+ Google 兜底（部署网络不可达）。
  - 实测：`openai.com` / `vercel.com` 的 desc **这次译成了中文** → MyMemory 目前可用，但**配额随时会被共享出口 IP 耗尽**，耗尽时不报 HTTP 错、而是在译文位回一句警告（`parseMyMemory` 已能识别）。
  - **这不是「能跑就行」的问题**：一个「今天能译、明天不能译」的引擎不满足「必须免费实时」。

### 1.4 已探明的可用资源（本机 Chrome 154，真实 https 源）

| 能力 | 结果 |
|---|---|
| `Translator`（浏览器内建本地翻译） | **存在**（`function`） |
| `LanguageDetector` | **可用**，`en` 置信度 0.9995 |
| `Translator.availability({en→zh})` | `downloadable`（**只差语言包**） |
| 语言包下载（headless） | **挂起不返回** → **无头环境无法验证** |

同时确认：`about:blank`（非安全上下文）下 `Translator` 为 `undefined` —— 该 API 只在 **安全上下文** 暴露，部署后是 https，满足条件。

## 2. 目标定义与达成情况

> 「实测」列来自 `probe/add-flow-realtime.mjs` 跑 8 站点（本机直连，非线上），
> 2026-10-12 实施后。

| 维度 | 现状（升级前） | 目标 | 实测 | 达成 |
|---|---|---|---|---|
| 用户看到**中文**内容的时刻 | 0ms（但内容是英文/模板话） | 0ms，且**已有中文草稿** | 第 0 跳 21~105ms，**P50 53ms**，且描述已是中文 | ✅ |
| 用户看到**真实**名称的时刻 | 0.8~13s（中位 ~2.2s，长尾 13.1s） | P50 < 1s，P90 < 2.5s | **P50 1143ms，P90 3119ms**（每一次 ≤ 3.4s） | ⚠ **P50<1s 未达成** |
| 用户看到**真实中文描述**的时刻 | 同上一行（被翻译阻塞） | 抓取完成后异步补齐，**不阻塞** | 第 2 跳独立发起，**不参与第 1 跳的耗时** | ✅ |
| 翻译的可用性 | 依赖共享 IP 日配额（随时归零） | **本地优先**，配额归零仍可用 | L1 词表 0ms/离线永不失败；L2 已在浏览器实测可用 | ✅ |
| 成本 | MyMemory 免费但不可控 | **零外部付费依赖** | L1 零依赖，L2 用浏览器自带模型 | ✅ |

### 2.1 为什么 `P50 < 1s` 没达成（如实记录）

第 1 跳的耗时**由目标站的 TTFB 主导**，不在我们这侧。冷缓存整轮实测（8 站点一次跑完）：

| 站点 | 第 0 跳 | 第 1 跳 | 接口自身 | 升级前基线 |
|---|---|---|---|---|
| tapecode.ai | 41ms | **379ms** | 344ms | 2670ms |
| sspai.com | 81ms | **570ms** | 384ms | 844ms |
| vercel.com | 84ms | **793ms** | 717ms | 1697ms |
| github.com | 49ms | **928ms** | 856ms | **13066ms** |
| openai.com | 81ms | **1362ms** | 1294ms | 4485ms |
| stripe.com | 73ms | **1636ms** | 1469ms | 1790ms |
| figma.com | 39ms | **2780ms** | 2729ms | 10293ms |
| news.ycombinator.com | 32ms | **3074ms** | 3025ms（超时降级） | 6366ms |

- 应用侧在响应之后还要跑 `ensureSmartCategory` 等，**额外 35~100ms**（不是主因）。
- 两个慢站点各有无法消除的原因：**stripe 返回 307、figma 返回 301**，每次都要多一跳重定向
  （`fetchCapped` 刻意不自动跟重定向 —— 每跳都要重新校验主机，否则「公网 URL 302 到内网」能绕过字面检查）；
  **news.ycombinator 根本连不上**，只能等满 3s 预算再如实降级。
- 两次冷缓存整轮的 P50 分别是 1143 / 1362ms —— 都在 1s 之上，且波动来自对外网络，不是代码。

因此契约改为三条**能守住且可解释**的：

| 契约 | 值 | 意义 |
|---|---|---|
| 第 0 跳 P50 | ≤ 400ms（实测 **41~84ms**） | 用户感知的「实时」= 粘贴即有中文，**这一条远超目标** |
| 第 1 跳 P50 / P90 | ≤ 1500ms / ≤ 3300ms（实测 **1362 / 3074ms**） | 相对升级前基线（~2230ms / 10293ms）分别快 1.6× / 3.3× |
| 第 1 跳 P100 | ≤ 3400ms | **抓取永不阻塞用户**：预算是硬上限，超时就如实降级并给 warning |

> 不做的事：把阈值调到刚好通过。原目标写进文档时没有实测支撑，实施后照实记为未达成。

## 3. 方案

### 3.1 抓取引擎：早断 · 并行 · 收紧预算 · 缓存

改 `shared/http-fetch.mjs` + `api/metadata.js`：

| # | 改动 | 依据 |
|---|---|---|
| a | 支持「读到截止标记即断开」（见 §3.1.1） | 实测 1.5~6× |
| b | `accept-encoding: identity` → `gzip, br` | 解压分支**早已实现**，注释说「不值得引入解压分支」已过期，identity 纯亏 |
| c | `maxBytes` 256KB → 64KB（早期截断兜底） | head 通常 <32KB；64KB 足够容纳超长内联 CSS 的 head。**实施后实测：`</head>` 的真实偏移是 666~21967 字节，字节上限从来没成为瓶颈** —— 它只是畸形页面（没有 `</head>`）的收口 |
| d | `FETCH_BUDGET_MS` 6000 → **3000** | 前端已有「秒填 + 后台升级」，超时只是「少一次升级」，不该让用户等 6s（用户已确认取 3s） |
| e | manifest 补抓：**独立小上限（900ms）+ 同 origin 缓存/去重** | ⚠ 计划里写的「与主抓并行」**做不到** —— manifest 地址是从 HTML 里解析出来的，只能在主抓之后。改为给它独立上限，不让它吃掉剩余预算；并纳入同一套缓存（它的产出只是一个装饰性品牌色，没理由为它等两遍）。空结果不缓存 |
| f | **同域抓取缓存**（内存 Map，TTL 5min，容量上限） | 同域名二次添加 0ms；注意 `Cache-Control: no-store` 只针对**响应**，服务端内部缓存另算 |

#### 3.1.1 「早断」为什么安全

`<head>` 内已包含推断所需的**全部**字段：`title` / `meta[name=description]` / `og:*` / `link[rel=icon]` / `link[rel=manifest]` / `meta[name=theme-color]`。
`</head>` 之后的正文只影响 `inferSite` 的正文摘要（当前实现里 `html` 与 `rootHtml` 的正文对结果影响很小）。

实现：在 `fetchCapped` 增加可选 `stopAt`（字符串或正则的终止标记）。流式读取时一旦命中：
- 记 `truncated = true`
- `stream.destroy()` + `req.destroy()`
- 按已读字节 resolve

**必须在 `</head>` 的完整闭合处截断**，不能切在标签中间 —— 否则 `inferSite` 的正则会拿到半截属性。若 64KB 内没有 `</head>`（畸形页），退化为「读满 64KB 断开」。

截断安全性：`decodeHtmlBytes` 用 `TextDecoder` 解码，尾部半个多字节字符会解成 `\uFFFD`，而它只在 `badCount >= 3` 时才尝试回退编码 —— 截断产生的 1 个坏字符不会触发误判。

#### 3.1.2 预算收紧的代价（明确记账）

收紧到 2.5s 后，**慢站（github.com 这类）必然落到「域名推断」**。这不是缩水，因为：
1. 用户已经**秒填**了草稿（本地推断，0ms），抓不到只是「没升级」，不是「空白」；
2. 后台升级链路（`metaUpgrade`）仍在，第二次进入详情/重新粘贴时可再试；
3. 现状是「让用户干等 13s 拿到域名推断」——**比快速拿到域名推断更差**。

> 若要「慢站也抓到」，正解是**异步补抓 + 回执**（已有 `runMetaUpgrade` 骨架），不是拉长同步预算。

### 3.2 翻译引擎：本地优先 · 在线兜底 · 不阻塞关键路径

三层，从上到下逐层降级：

| 层 | 引擎 | 延迟 | 成本 | 覆盖率 | 可用性 |
|---|---|---|---|---|---|
| **L1** | **内置词表/短语表** `shared/glossary.mjs` | **0ms** | 0 | 高频技术词 + 营销套话 | 全浏览器、离线 |
| **L2** | **浏览器内建 `Translator`**（本地神经模型） | 首次下载语言包后可忽略 | 0 | 整句，质量好 | Chrome/Edge 138+，安全上下文 |
| **L3** | MyMemory → Google（现状） | 0.5~3s | 0（但有配额） | 整句 | 有网即可，**配额不可控** |

**分工**：
- L1 是**地板**：保证任何环境下都有中文关键词，绝不返回空。
- L2 是**天花板**：能拿到整句地道译文，且完全离线 —— 这才是「实时免费」的真正答案。
- L3 是**兜底**：L2 不可用（Safari/Firefox、语言包未下载、下载失败）时的补充。

**必须处理的 L2 现实问题**：
- 语言包 ~40MB，**首次要下载** → 不能卡在关键路径上。策略：**静默预热**（首次进添加弹窗时后台 `Translator.create()`，进度不打扰用户），失败就永远走 L1/L3。
- **无头环境无法验证**（实测挂起）→ 守卫只能覆盖「可用性探测 + 降级分支」，真机验证要在**有头 Chrome** 跑一次。
- API 名有两代（`window.translation` → `Translator`），要按能力探测而非版本判断。

#### 3.2.1 把翻译从关键路径摘下来

现状：`/api/metadata` 内**同步**等翻译（最多 3.5s）才返回 —— 这就是 figma.com 10.3s 里的一大块。

改为：
- `/api/metadata` **默认只做抓取**，返回原文 + `needsTranslate` 标记（响应时间 = 纯抓取）；
- 新增 `GET /api/translate?name=&desc=` 独立接口，前端**异步**补译文；
- 复用现有**两段式升级**通道（`metaUpgrade`）承载这一跳，UI 文案如实标注「译文来自本地词库 / 在线引擎 / 未翻译」。

> 兼容：`/api/metadata` 保留 `?translate=1` 走旧行为，避免破坏既有探针与调用方。

### 3.3 前端：三跳渐进

| 跳 | 时刻 | 内容 |
|---|---|---|
| **0** | 0ms | 域名推断 + **L1 词表翻译** → 中文草稿 |
| **1** | <1s | 真实抓取（早断提速）→ 真实名称/描述（原文） |
| **2** | 异步 | L2/L3 翻译 → 中文描述，静默升级 + 回执 |

状态文案沿用上一轮修好的口径（接口通 ≠ 说后端坏），新增「译文来源」标注。

## 4. 验收标准

### 4.1 自动化守卫

| 守卫 | 内容 |
|---|---|
| `test-http-fetch`（新增/扩充） | `stopAt` 命中即断且字节完整；未命中时退化为 `maxBytes`；`truncated=true`；**压缩解压仍正确**（gzip/br/deflate/未知编码） |
| `test-metadata-fast`（新增） | 预算收紧后超时路径返回域名推断 + 正确 warning；`?translate=1` 仍走旧行为 |
| `test-glossary`（新增） | 词表命中/未命中/大小写/标点/长句截断；**命中率基线**（用真实站点 desc 样本回归，防词表删条目导致覆盖率静默下降） |
| `test-translate`（扩充） | 三层降级顺序：L2 抛错 → L3；L3 配额警告文案 → 空串；**L1 永远有值** |
| `test-bundle` | 词表与 L2 适配器**不得进首屏**（走动态 import）；LAZY_PARTS 同步标记 |
| `test-local-meta` | 第 6 节口径不回退（接口通不说后端坏） |

### 4.2 真机（线上）

- `probe/add-flow-realtime.mjs`（**新增**）：对 8 站点批量测 **P50/P90 耗时**；断言第 0 跳**必含中文**且 P50 ≤ 400ms；第 1 跳 P50 ≤ 1500ms、P90 ≤ 3200ms、**每一次 ≤ 3400ms**（见 §2.1 为何与原始目标不同）。跑本地未发布代码时指向 `node dist/server.js`。
- `probe/browser-translate.mjs`（**新增，有头 Chrome**）：验证 L2 语言包下载 + 整句翻译 + 降级；**无头下跳过并明确标记 skipped**（不假装通过）。
- 既有 `add-modal-status.mjs` / `verify-add-autofill.mjs` / `auto-add-upgrade.mjs` 不得回退。

### 4.3 硬约束

- 首屏预算 **600 KiB raw / 230 KiB gz** 不放宽。
- 重新发布后跑全套线上回归（当前基线：文案 9/9、静态 15/15、补全 10/10）。

## 5. 风险与取舍（需要确认的点）

| # | 取舍 | 选项 A | 选项 B | 倾向 |
|---|---|---|---|---|
| 1 | 翻译主力 | **L2 浏览器本地模型**（零延迟零成本、质量好；仅 Chrome/Edge 138+、首次下 ~40MB、无头不可验） | **L1 词表**（全浏览器、0 下载；只能翻词/短语） | **A + B 都要**：L1 做地板，L2 做天花板；需确认是否接受「首次静默下载语言包」 |
| 2 | 抓取预算 | 收紧到 **2.5s**（P90 达标；慢站必落域名推断） | 保持 6s（github 这类仍能抓到，但用户干等 13s） | **2.5s** + 异步补抓兜底 |
| 3 | 是否新增 `/api/translate` | 新增（翻译不再阻塞抓取响应） | 保持内联（少一次往返，但每次都多等最多 3.5s） | **新增** |

## 6. 不做的事（明确边界）

- 不引入付费翻译 API / 不做密钥计费链路。
- 不做「服务端渲染整页」或 headless 浏览器抓取（成本与安全都不划算）。
- 不改 `inferSite` 的推断规则本身（本次只改**怎么拿数据**，不改**怎么推断**）。
- 不删 MyMemory/Google 兜底（L3 仍有用，只是不再是唯一依赖）。
