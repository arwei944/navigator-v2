# 筛选条压到两行 —— 设计文档

日期：2026-10-16
范围：主站筛选条（`src/components/FilterBar.vue`）
需求原话：「这个占据了太多的空间，我需要最多不超过两行」（附筛选条截图）
方案选择：用户在三个方案里选了「精简 + 更多弹层」

---

## 0. 需求

筛选条总高**最多两行**。

## 1. 现状（改动前）

筛选条最多会到 5–6 行：

| 行 | 内容 | 行数 |
|---|---|---|
| 第 1 行 | 方向分段控件（全部 / AI 学习 / 币圈 / 工具 / 基础服务） | 1 |
| 第 2 行起 | **「全部」时把所有方向的子分类一次性铺开**（4 组 33 个标签） | 4 |
| 最后一行 | 用途标签（12 个，独立的 `.purpose-row`） | 1 |

第 2 段的注释写着「一屏看全，无横向滚动条」—— 那是有意的设计取舍，代价就是行数不可控。
「选了某个方向」时会收敛到该方向的标签，但默认状态（全部）永远是最高的那一种。

## 2. 方案

**第一行不变**（方向 tab）。**第二行只留最常用的 8 个标签**，其余分类与用途一起收进「更多」面板。

### 2.1 第二行显示什么：抽成纯函数

`src/utils/filterChips.js#pickInlineChips(chips, pinned, max)`：

- `pinned`（已选中的分类 / 用途）**永远留在行内、排在最前**；
- 其余按站点数降序补足到 8 个，计数相同时保持原顺序（稳定），否则刷新一次就换一批标签。

抽出来的理由：这是「哪些标签看得见」的唯一判据，也是最容易悄悄出问题的地方 ——
已选中的标签一旦被计数挤出可视区，用户看不见自己选了什么，只会以为筛选失灵。
纯函数才能被纯 node 测试锁住（20 条断言）。

已选项跨轴（用途不在分类候选里）也要能 pin：pinned 元素带 `kind` 标记，
点击时据此决定走 `selectCategory` 还是 `selectPurpose`。

### 2.2 「更多」面板

- 收纳**全部**分类（按方向分组，与「全部」时的原分组一致）+ 用途一组，选中态照常高亮；
- 选完自动收起（不必再点一次「更多」）；Esc 与点击面板外也收起；
- 渲染模型 `panelGroups` 把「分类各组 + 用途一组」合成一条渲染路径 —— 两块标记结构完全一样，
  只有「哪个是选中值、点击落哪个动作」不同，拆两段写等于把同一段模板抄两遍。

### 2.3 两个位置上的决定

**① 面板是同列内展开，不是浮层。** `.main` 是 `overflow: hidden` 的 flex 列容器，
绝对定位的浮层会被直接裁掉。展开面板把下方卡片区下压（`.main` 是 flex 列，
FilterBar `flex-shrink: 0`，卡片区 `flex: 1`），不覆盖内容、不与卡片抢层级。

**② 「更多」放在横向滚动区之外。** 第二行强制单行（`flex-wrap: nowrap` + `overflow-x: auto`，
滚动条隐藏），标签溢出时可横滑。**这是截图逮到的**：初版把「更多」和标签放在同一个滚动容器里，
标签一溢出，最先被切掉的恰好是唯一的入口 —— 按钮只露一半。现在结构是
`.chip-row-wrap > (.chip-row[滚动] + .more-btn[固定])`，入口恒定贴右端。

### 2.4 数据与交互不变

域 / 子分类 / 用途三轴的筛选语义、URL 参数（`c` / `p`）、计数基准（跟随收藏范围、
用途按分类轴收窄）全部照旧，只换呈现。`selectCategory` 的「再点一次退回所属域」也照旧。

## 3. 配置

无新增配置项、无环境变量、无接口改动。纯前端组件与一个纯函数模块。

## 4. 验收

| 项 | 方式 | 结果 |
|---|---|---|
| 取数规则（pinned 优先 / 上限 / 稳定排序 / 脏数据） | `tools/console/test-filter-chips.mjs` | 20 条断言 |
| **渲染后真的只有两行** | `probe/filter-bar-verify.mjs`（真机） | 27 条断言 |
| 首屏预算 | `tools/console/test-bundle.mjs` | 612.6 ≤ 614 KiB |
| 无回归 | `console:test:all` | 60 个脚本 |

真机探针覆盖：行数（`offsetTop` 去重后必须为 1）/ 总高 ≤ 方向 tab + 标签行 + 间隙 /
行内标签数 ≤ 8 /「更多」完整可见且与内容区右边界对齐（打印几何数值，不靠肉眼）/
面板内容与分组 / 面板在筛选条下方 / 面板里选中最冷门分类后 URL 生效且面板自动收起 /
**已选中的冷门标签仍在行内可见** / Esc 与点击外部收起 / 420px 窄屏仍是一行 / 无控制台异常。

首屏预算 612 → 614 KiB：实测（暂存改动前后各构建一次）610.7 → 612.6，净增 1.9 KiB，
全部落在首屏组件自身（筛选条就在首屏，懒不掉）。这是本项目今天第三次按同一口径抬预算，
每次都在 `test-bundle.mjs` 里写明实测值与来源。

## 5. 不做的事

- **不改三轴筛选的结构**：域 / 分类 / 用途的关系没动，只动呈现；
- **不做「更多」面板的搜索框**：33 + 12 个标签一屏看得完，加搜索是过度设计；
- **不给第二行加渐变遮罩**：「更多」已是常驻入口，再叠一层视觉提示只是噪声；
- **不做标签自定义排序 / 隐藏**：那是另一件事（用户偏好持久化），不在本次范围。
