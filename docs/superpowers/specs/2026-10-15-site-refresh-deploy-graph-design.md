# 站点信息重新获取 · 部署管理模块 · 网站关联图谱

三件事一次交付，共同点是它们都在回答「**看清**」这类需求：看清一个站点的最新信息、
看清线上跑的是哪一版、看清站点之间为什么相关。

- 站点重新获取：已经收进来的站点，信息会过期，得能按需重抓。
- 部署管理：线上跑的是哪次构建、和本地差多少、怎么安全地推上去。
- 关联图谱：站点不是孤岛，关系本身就值得看。

---

## 0. 需求与动机

### 0.1 站点信息重新获取

站点入库时抓的是**当时的**元信息。半年前抓的站点，现在名字可能改了、描述过期了、
图标挂了。项目里其实早就有「秒加补全」在用的 `runMetaUpgrade`（抓真实信息 + 翻译 + 回写），
但它有两个守卫让它无法直接复用：

1. 它按 `updatedAt` 判断「这个站是不是刚建的」，站点建好后就不再触发；
2. 它写在自动添加链路里，没有面向「用户主动要求刷新」的入口。

所以缺的**不是抓取能力，而是入口**。

### 0.2 部署管理

现状是分裂的，而且分裂得有道理：

| | 站内后台（/admin） | 本地控制台（tools/console） |
|---|---|---|
| 已有面板 | 云端发布 / 快照回滚 / 发布历史 / 操作审计 | 同步 / 历史 / 数据 / 可用性 … |
| 管的是 | **站点数据**进云端 Blob | 站点数据 + 本地运维 |
| 代码部署 | 无 | **无**（一直是手敲命令） |

也就是说：**代码部署这件事从头到尾没有可视化**。每次发版靠人工执行
「构建 → 打包 → curl 上传 → 重启 → 验证」，中间任何一步失败都只有终端里的滚动日志。

而且有一个硬约束决定了架构：**站点自己不能部署自己**。它的产物里只有构建结果，
没有源码、也没有平台的发布凭据。要让线上那个站自发布，就得把凭据塞进公开的前端产物。
所以职责必须切开：**站内只能看，本地控制台才能做**。

### 0.3 网站关联图谱

站点库有 300 条数据、分类、用途、描述、别名 —— 但除了列表与筛选，这些关系没有出口。
用户想知道的是「这几个站为什么被放在一起」「还有哪些站跟它是一路货」。

---

## 1. 现状（先量后改）

- 站点数 300，分类 12 个，每条站点有 `categoryId` / `purposes` / `desc` / `aliases`。
- 已有图表底座 `utils/chartkit.js` 只有 sparkline / donut / heatstrip / barTrack —— **没有图布局**。
- 已有 `shared/glossary.mjs#extractKeywords` 能提概念词，但实测**对中文描述抽不出词**
  （库里描述绝大多数是中文），所以关联引擎需要用中文语料来定概念表。
- 构建链路：`vite build` → `scripts/postbuild-spa-fallbacks.mjs`（SPA 兜底 + 复制 `server/`、
  `api/`、`shared/` 进 dist，并写 dist/package.json）。
- 平台（BotKeep）上传通道限制：**ZIP 通道 ≤200 文件 / ≤5 MB / 不支持二进制**，
  而产物是 412 文件 / 8.9 MiB / 270 个二进制图标 —— 这条路走不通，必须 tar 切片。

## 2. 方案

### 2.1 站点信息重新获取

**入口**（两处，覆盖单点与批量）：

- `EditSiteModal` 网址行右侧加「重新获取信息」按钮；
- 后台站点管理的批量条加「重新获取信息」（**串行**刷新选中项，带进度）。

**编排**（新模块 `src/services/siteRefresh.js`）：

复用 `runMetaUpgrade` 的写回 patch（`upgradePatchFromMeta`），只换两个语义：

1. 守卫从「刚建的站才升」改为**用户显式要求**（按钮就是意图）；
2. 抓到的值先写库，**再同步回表单** —— 否则用户眼前还是旧名称，一按保存就把刚抓到的
   覆盖回去，刷新等于白做（这是本次真机逮到的缺陷）。

**边界**：只改页面能抓到的字段（名称 / 描述 / 图标），**不动**分类、用途、别名 ——
那些是用户手填的判断，不该被一次抓取抹掉。

### 2.2 部署管理

分两层，各做各能做好的事。

#### 2.2.1 站内（只能看）

- 构建时生成 `dist/build-info.json`（sha / 短 sha / 分支 / dirty / 提交标题 / 构建时间）。
  **刻意不写进前端产物**：它描述「这次构建」，而面板要回答「线上正在跑的是哪次构建」——
  构建了新包但还没部署时，这是两个不同的事实，混在一起会给出误导结论。
- 新接口 `GET /api/deploy-status`（公开只读）返回四块：版本、运行时（Node/uptime/内存/端口）、
  数据（站点数/版本/更新时间/数据目录体积）、定时巡检状态。
- 后台新增「部署」tab（`AdminDeploy.vue`）：展示上述内容，外加「检查更新」——
  比对线上 sha 与 GitHub 上游 master，直接告诉用户**落后几个提交、都是哪些提交**。

**安全边界**（公开接口的硬要求）：不含任何凭据材料；`data/` 只回汇总数字，
**不回文件名**（`admin-key.txt` 这个字符串出现一次就等于给出了攻击目标）；
不回站点内容。测试里对这份清单逐词断言（`test-deploy-status.mjs`）。

#### 2.2.2 本地控制台（才能做）

新模块 `tools/console/lib/deploy.mjs` 编排完整发布：

```
构建 → 发布门禁(deploy-cloud --check) → 打包(tar，排除 data/)
     → 切片上传(逐片、带重试) → 触发容器解压 → 线上验证(轮询版本一致)
```

新端点 `/api/deploy/status|credentials|publish`，新面板 `ui/deploypanel.js`（「发布」tab），
发布走**任务 + SSE 实时日志**（构建/上传/重启是分钟级动作，没有流就只能干等）。

凭据（BotKeep API key 与 workload id）从本机 `.env.local` 读，未配置时面板给输入框就地写入；
**只写本机、不进前端产物、不进版本库**。

平台约束在代码里显式处理（都是踩出来的）：

- 幂等键必须 16–64 位字母数字加 `-`/`_`，**先自校验，不合格直接抛** ——
  写短了服务端回 422，而这条错误看起来像瞬时故障，会被重试逻辑吞掉（实测白等过 9 分钟）；
- 429 是**排队 40–80 秒后**才返回，重试间隔取 45 秒，否则重试本身也在排队；
- `data/` 打包时排除，且在打包后**再断言一次**它没进包。

### 2.3 网站关联图谱

#### 规则引擎 `shared/affinity.mjs`

五个因子加权，**每条边都必须说得出理由**（这是选规则而不是选黑箱的前提）：

| 因子 | 权重 | 理由文案 |
|---|---|---|
| 同分类 | 40 | 同属「入门对话」 |
| 共同用途 | 10/个，上限 30 | 都用它来「AI 对话、学习」 |
| 共同概念词 | 8/个，上限 24 | 都在讲「AI」「交易」 |
| 同一注册域 | 25 | 同一个站点家族（binance.com） |
| 名称/别名互含 | 15 | 名称/别名互相包含 |

概念词表从**真实 300 站语料**统计得出（不是拍脑袋列的），中文为主。

两个入口共用同一个引擎、同一个阈值：

- `buildAffinityGraph(sites)` —— 织整张网（图谱页用，300 站 580 条边约 120 ms）；
- `relatedTo(site, sites)` —— 单点查询（站点详情的「相关站点」用，毫秒级）。

**刻意不做 topK 对称修剪**在单点查询里：那是「画图」的约束（防糊成一团），
而详情页只想知道「谁跟我最像」，被别处剪掉不该影响答案。

#### 力导向布局 `src/utils/graphLayout.js`

自写 FR（斥力 + 引力 + 分类锚点 + 冷却），因为引 d3-force 会往懒加载 chunk 里加一个
只为「算 300 个坐标」的大依赖。

**参数是实测扫出来的，不是拍的**（300 站真机数据、1400×900 画布）：

| repulsion / anchorPull / anchorScale | 簇分离比 | 贴边率 | 网格占用 | 最近邻 |
|---|---|---|---|---|
| 1 / 0.06 / 0.82（初版） | 5.46 | **97%** | 44/126 | 10.4 |
| 0.3 / 0.7 / 0.5（现值） | **6.40** | **6%** | 80/126 | 19.3 |

初版那两个系数的**量级**是错的：斥力按「每一对节点」累加，锚点力却只有一项，
300 个节点的斥力净和把那点弱锚点力彻底压过去 —— 整张图一路膨胀到撞上画布边界被夹紧。
真机截图上是一个**空心方框**：节点沿四边排成线、中心全空。
单测当时只验了确定性 / 夹紧 / 性能，**一条都没拦住它**。

#### 图谱页 `views/GraphView.vue`

- SVG 画布，缩放 / 平移只改外层 `<g>` 的 transform —— 900 个图元的坐标不动，
  拖拽与滚轮不触发上千次节点 diff；
- 节点按分类着色、大小按连接数；**默认只给连接数前 24 个节点露名字**
  （不用「度数 ≥ N」这种绝对阈值：实测会一次放出 143 个标签，必然互相压字）；
- 点节点出详情：相关站点 + 关联分数 + 可读理由，点邻居可以继续走（顺着关系探索）；
- 「只看邻居」收敛成子图；分类筛选与阈值滑块会重算（150 ms 防抖，松手才算）。

#### 站点详情里的「相关站点」

`components/right/RelatedSites.vue`，异步引入（它带着 affinity 引擎，而面板在首屏）。
新增区块开关 `related`（默认开）。

## 5. 不做的事

1. **站内后台不做「一键部署」**：产物里没有源码与发布凭据，要做就得把凭据塞进公开前端。
   站内只汇报状态，动作留在本地控制台。
2. **不做整页截图式预览**：与关联度无关，且要额外一次网络往返与渲染进程。
3. **不做「站点自己回滚」**：回滚同样是发布动作，归控制台。站内的快照与回滚管的是**站点数据**，
   与代码版本是两件事，刻意不混。
4. **关联度不引入第三方图库**（d3-force / cytoscape）：只为算 300 个坐标加一个按需依赖不划算。
5. **关联度不做「AI 判断两站是否相关」的默认路径**：规则版每条边都有可读理由、
   毫秒级、可离线；AI 版是另一条独立的、需要凭据的链路，不塞进主路径。

## 6. 本轮顺带修掉的两个既有缺陷

1. **控制台前端模块图整体加载失败**：`tools/console/server.mjs` 的 MIME 表没有 `.mjs`，
   `/shared/host.mjs` 以 `application/octet-stream` 返回，而浏览器对 module script
   **强制校验 JavaScript MIME**。表现不是 404，而是「页面看着好好的、按钮全都没接上」。
   这一条在本轮之前就存在，只是因为没人从 UI 层验证过控制台而一直没暴露。
2. **探针的假阴性**：探针没调 `Runtime.enable`/`Page.enable`，于是
   「没有异常」是一句什么都没验证的话。已修，并给控制台加了启动期错误留痕
   （`window.__navBootError`），这类「静默不执行」的故障以后一眼可见。
