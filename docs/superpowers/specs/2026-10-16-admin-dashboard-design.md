# 管理后台 · 卡片仪表盘 —— 设计文档

日期：2026-10-16
范围：管理后台中间区（`src/views/AdminView.vue`）
决策来源：在 20 种布局决策页里，用户先选 L01（顶部标签），我按「在它基础上升级完善」保留了骨架；
上线后用户反馈「管理后台布局还是没有更改」——**骨架没换，所以看不出来**。
这一轮明确选了 **⑥ 卡片仪表盘**。

---

## 0. 需求

中间区不再是「一排 tab + 单面板」，而是**铺满的模块卡片**。

## 1. 为什么上一轮「看不出变化」

L01 就是「现状基线」，我把它理解成「保留骨架、补掉已知代价」，于是只改了三处**细节**：
分组分隔线、装不下时收进「更多」、键盘 ←/→。

更糟的是：**在用户的窗口宽度下（约 1930px）13 个 tab 全能塞下，「更多」根本不出现** ——
本次升级里最实质的那一项，在他屏幕上天然不可见。可见的只剩几条细分隔线。

教训记在这里：**用户说「升级完善」时，先问清楚「你期望看到什么变化」**，
不要默认他会满足于「代价被补掉但样子没变」。这次是问了之后才对齐的。

## 2. 方案

### 2.1 仪表盘 = 原「概览」面板，不是新增一页

| 组成 | 来源 |
|---|---|
| 4 个 KPI（站点 / 分类 / 今日访问 / 收藏） | 原概览面板，原样保留 |
| 12 张模块卡片 | 新增 |
| 数据洞察（分类分布 / 点击量 TOP10） | 原概览面板里的 `AdminInsights`，原样保留 |

理由：不新增页面、不丢任何现有内容，只是把「概览」重排成「一屏看到所有模块」。
tab 行的第一个入口因此改名为**「仪表盘」**（id 仍是 `overview`，快捷键与深链接不受影响）。

### 2.2 仪表盘上收起 tab 行

卡片本身就是导航，所以仪表盘上不渲染 `.admin-tabbar`；**进模块后 tab 行出现**，
承担「切模块 / 返回仪表盘」。这样「不再是 一排 tab + 单面板」是**看得见**的，
而不是「下面换了张图，上面那条 tab 还在」。

### 2.3 卡片铺满：`auto-fill` 而不是固定列数

```css
grid-template-columns: repeat(auto-fill, minmax(230px, 1fr));
```

中间区宽度会随两侧栏折叠、窗口缩放变化（三栏壳下 900px～1400px 都可能），
**固定列数必然在某档宽度下留出大片空白** —— 这正是「布局不自适应」的来源。
卡片用 flex 列 + `margin-top:auto` 让「数字」和「进入 →」在任何高度下都对齐底部。

### 2.4 卡片上的数字：拿不到就不写

只放**页面上已经拿得到**的：站点数、分类数、部署版本、云端版本、通知未读数。
其余 7 个模块**只给一句话说明、不给数字** —— 宁可不显示，也不编一个好看的数
（这是本项目反复强调的口径，也是我在 20 布局决策页里犯过的错的教训）。

## 3. 验收

| 项 | 方式 | 结果 |
|---|---|---|
| 仪表盘渲染 | `probe/admin-tabnav-verify.mjs`（真机，含线上） | 12 张卡 / tab 行不渲染 / 网格占内容宽 ≥95% / 每行 ≥3 张 / 无 `undefined`·`NaN` |
| 点卡片进模块、再回仪表盘 | 同上 | 进「插件」→ `?tab=plugins` + tab 行出现；点「仪表盘」→ 回到卡片页 |
| **重复标题守卫** | 同上 | 仪表盘内 h2/h3 文案不许重复（本项目被「渲两遍」咬过两次） |
| 导航升级（分组 / 更多 / 键盘） | 同上，全部在模块页里复验 | 22 条 |
| 无回归 | `console:test:all` | 62 个脚本 |

**探针自身要改**：原来它启动后就等 `.admin-tabs`，而仪表盘上 tab 行不存在 ——
这会让一支好探针变成「一启动就失败」。改成等 `.admin-view`，
并在仪表盘断言之后再点卡片进模块，导航断言全部挪到模块页里做。

**截图逮到的缺陷**：初版我在 `AdminInsights` 上方又加了一个「数据洞察」标题，
而该组件自带同名标题 → 页面上出现两个「数据洞察」。已删掉我加的那个，
并补了「仪表盘内标题不许重复」的断言。

## 4. 不做的事

- **不改 13 个面板的内部布局**：本次只动中间区的组织方式，面板组件一行未改。
- **不做卡片自定义排序 / 隐藏**：那是用户偏好持久化，另一件事。
- **不给卡片加缩略图 / 图表**：卡片负责「这是干什么的 + 一眼状态」，进去才看细节。
- **不删任何现有内容**：KPI 与数据洞察都留着，只是重新排布。

## 6. 第二轮（同日）：卡片补真实摘要 + 面包屑取代 tab 行

用户看完第一轮线上效果后说「全部处理好」，指的是我提的两件事。

### 6.1 卡片补真实摘要

**数据怎么来**：不新造聚合大接口，也不为 7 个数字发 7 个请求，而是三条**并行** GET：

| 卡片 | 来源 |
|---|---|
| 发布历史 / 操作审计 / 通知中心 | `GET /api/ops?summary=1`（**新增**） |
| 插件 | `GET /api/plugins?light=1`（**新增**，跳过逐个 provider 的可用性探测） |
| 快照与回滚 | `GET /api/sites?snapshots=1`（既有） |
| 站点 / 分类 / 部署 / 云端发布 | 页面本地已有（store 与版本标识） |

`?summary=1` 复用 `api/ops.js` 里三个动作**同一批读者与汇总函数**
（`summarizeRecords` / `summarizeEntries` / `summarizeNotifications`），
所以卡片上的数字与点进去面板里的总数**必然一致** —— 真机断言就是逐个比这两者。

**为什么不做成一个聚合接口**：这三份数据分属数据面 / 运维面 / 插件清单，
`api/ops.js` 头部专门解释过为什么要把它们分开（数据面不能因为运维面的 bug 变脆）。
三次并行 GET 换来分层清楚，值。

**备份与恢复 / 偏好设置 / AI 助手仍只有说明**：它们没有「数字型」的实时状态，
硬塞一个数只会是假信息 —— 宁可不显示。

### 6.2 面包屑取代 tab 行

模块页顶部从「一排 tab」换成 `← 全部模块 / 运维 / 插件`，仪表盘上则完全不渲染。
配合上一轮的「仪表盘上也不渲染 tab 行」，**整条 tab 栏退出后台**。

**随之退役并已删除的代码**（不留死代码）：

| 删除项 | 原因 |
|---|---|
| `src/utils/tabOverflow.js` + `test-tab-overflow.mjs`（26 条断言） | 溢出计算只服务于 tab 行 |
| 溢出「更多」面板 / 键盘 ←→ / 度量逻辑 | 同上 |
| 布局切换（横排 / 竖排，即早前 21 项里的 #20） | 没有 tab 行，两种排布都无意义 |
| `package.json` 里的 `console:test:tab-overflow` | 测试随之删除（61 脚本） |

保留：`TAB_GROUPS`（面包屑要显示分组）、`g` 前缀快捷键（仍能切模块）、13 个面板组件一行未改。

### 6.3 真机逮到的产品缺陷

卡片模板写的是 `v-if="m.value"` —— 而 **`0` 在 Vue 里是 falsy**，
所以真实的 0（审计 0 条、未读 0）**什么都不显示**。本地库是空的，一跑就露出来了。
改成 `v-if="m.value !== ''"`。

### 6.4 验收

| 项 | 结果 |
|---|---|
| `probe/admin-shell-verify.mjs`（原 tabnav 探针改名重写） | **25 条**，本地 + 线上各一遍 |
| 其中「数字与面板一致」 | 发布历史 / 审计 / 通知三处逐个比对服务端两个接口的返回 |
| 卡片摘要 | 9/12 张带真实数字（本地库为空时也如实显示 0） |
| 面包屑 | 出现「← 全部模块 / 分组 / 模块名」；tab 行数为 0；能返回 |
| 快捷键 | `g + s` 仍能切到站点管理 |
| 无回归 | `console:test:all` **61 脚本**；构建 + 首屏门禁通过 |

**探针自身又踩了一次同一个坑**：比较用的 async 表达式走 `jsonOf` → 它的包装函数不会 await，
async 结果被序列化成 `{}`。改用 `evalJs`（带 `awaitPromise`）+ 页内 `JSON.stringify`。
