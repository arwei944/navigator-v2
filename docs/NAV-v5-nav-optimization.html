01

现状体检：V5 导航由什么构成

先把事实摆清楚。以下全部来自 git show HEAD: 的 V5 源码与线上站点实测，不含推测。

骨架与布局模型

src/App.vue · src/styles/main.css

header.mobile-headerdisplay:none，无媒体查询覆盖 → 永不显示
aside.sidebar240px（inline minWidth）
折叠 60px / 拖拽 160–400
main.mainflex:1，无 min-width
StatsBar→时钟→Google→搜索→卡片工具栏
aside.right-sidebar280px（min-width 280）
可折叠为 0
.app-layout { display:flex; height:100vh } —— 三栏并排，滚动在各自容器内部移动端仅有一条规则：@media(max-width:768px){ .main{margin-left:0!important} }（flex 布局下该属性无效）
两侧栏都是 硬宽度 + min-width（240 + 280 = 520px），flex 无法压缩它们，于是 main 被压到 0。这是移动端不可用的根因。

导航状态模型

stores/sidebar.js · stores/sites.js · App.vue

导航由四条互相独立、部分重叠的状态轴共同决定，但它们之间没有统一语义：

  • activeNav ∈ 发现 / 分类 / 收藏 / 最近 / 内容聚合 / 回收站 —— 视图轴，仅存于内存
  • currentCategory —— 筛选轴，同步到 /category/:id
  • searchQuery —— 同步到 ?q=
  • sortBy / viewMode —— 不进 URL，不持久化
四条轴里只有两条进 URL。切换「收藏 / 最近 / 回收站 / 内容聚合」不产生历史记录、刷新即丢、无法分享。这是导航层最实质的可达性缺陷。

问题清单（18 条，按性质分组）

每条都附源码或实测证据。严重度：P0 = 功能不可用 / P1 = 效率与可达性 / P2 = 打磨。

编号问题证据影响严重度
A1 移动端内容区宽度为 0 375px 实测：aside.sidebar=229px、.right-sidebar min-width=280px、main.main=0px 手机上完全看不到站点，产品等于不可用 P0
A2 移动端顶栏从未渲染 MobileHeader.vue 的 .mobile-header{display:none} 没有任何媒体查询覆盖；DOM 中宽度为 0 汉堡入口不可达，抽屉机制形同虚设 P0
A3 无拇指可达的主导航 全站没有底部导航栏；移动端唯一的导航是侧栏抽屉 单手持机时一级导航位于最难触及的左上角 P0
B1 6 个视图项里 2 个是空壳 CardsContainer 的 displaySites switch 只处理 favorites / recent，discover 与 categories 落到 default 分支，行为与默认完全相同 点击「发现」「分类」界面毫无变化，用户怀疑功能坏了 P1
B2 视图状态不进 URL App.vue 仅 watch currentCategory 与 searchQuery；activeNav 无任何路由同步 收藏 / 最近 / 回收站 / 聚合 不可分享、不可收藏、刷新丢失、返回键无效 P1
B3 「分类」一词承担两种含义 侧栏既有名为「分类」的视图项（只改高亮），又有分类列表；选中分类时还会把 activeNav 置为 categories 用户无法判断「分类」是视图还是筛选器 P1
B4 视图与筛选互相隐式改写 navigate('favorites') 内部调用 setCategory('all')；选分类又改写 activeNav 状态跳转不可预期，用户不知道自己「离开」了收藏视图 P1
B5 「最近」语义与入口不一致 侧栏「最近」= 按 createdAt 倒序取前 24 条收录时间 命名为「最近」却与浏览历史无关，用户预期落空 P2
C1 31 行导航默认全展开 CATEGORY_GROUPS 四组的 collapsed 初值均为 false 侧栏内部滚动；30 个分类里找一个靠滚动而非检索 P1
C2 导航内没有分类检索 侧栏无过滤输入框 分类规模一旦增长，查找成本线性上升 P1
C3 「全部」与域分组头视觉同级 .sidebar-category（全部）与 .category-group-header 相邻渲染 层级关系读不出来，域的归属感弱 P2
D1 首屏 5 层 chrome StatsBar → 时钟 → GoogleSearchBar → SiteSearchBar → .cards-toolbar → 卡片 笔记本高度下卡片被推到折叠线以下，首屏几乎看不到内容 P1
D2 三个搜索入口并存 SiteSearchBar（站内）+ CommandPalette（Ctrl+K）+ GoogleSearchBar（外站） 注意力被稀释，用户要判断「该用哪个框」 P1
D3 同类控件分散两处 排序 / 视图切换在 StatsBar；批量 / 拖拽在 .cards-toolbar 「整理站点」的心智动作被拆散 P2
D4 低价值组件占据黄金位置 数字时钟独占一行；StatsBar 占据首屏第一行 用最贵的版面换最弱的信息 P2
E1 键盘无法激活导航项 侧栏项为 div[tabindex=0][role=button]，只绑 @click，无 keydown 处理 键盘用户能聚焦却按不动，等于导航不可用 P1
E2 伪 listbox 语义 role="listbox" / role="option" 但没有方向键导航、没有 aria-activedescendant 读屏播报与真实交互不符，误导辅助技术用户 P2
E3 缺少跳转到主内容的 skip-link 页面无 skip 链接 键盘/读屏用户每次都要穿过整条侧栏 P2
V5 已有的好底子，不要动：侧栏折叠（60px 图标态）+ 拖拽调宽（160–400px）+ versionedPersist 持久化；域分组可折叠的数据结构（shared/categories.mjs 单一数据源）；站内搜索的建议下拉与键盘选择；收藏/回收站角标。这些是本轮改造的资产，不是负担。
03

设计目标与原则

先把「为什么」定下来，后面的取舍才有依据。

核心任务（JTBD）

主任务：「我想去那个网站」—— 在最短路径内找到并打开。

次任务：「我要整理我的站点集合」—— 收藏、添加、归类、清理。

偶发任务：换主题、导入导出、看统计。

当前实现把三类任务的入口平等地堆在一起：主任务的分类列表被 30 行淹没，偶发任务（主题/导入导出）却占了侧栏固定位置。原则就是按任务频率重新分配版面。

六条设计原则

  • P1 单一导航模型：把「在看什么范围」与「怎么筛」彻底分开，一个状态只由一个轴决定。
  • P2 状态即 URL：任何导航状态都必须可直达、可刷新、可回退、可分享。
  • P3 拇指优先：移动端一级导航放在底部，单手可达。
  • P4 渐进披露：低频项（主题、导入导出）不占导航位，收进设置。
  • P5 内容优先：首屏 chrome 总高度设上限，控件紧贴它作用的对象。
  • P6 键盘等价：能用鼠标完成的导航，键盘必须能完成。

方案 A · 保守微调

不推荐

不推荐

关键界面改造（前后对照）

R1 · 移动端：从「不可用」到「可用」

现状 375px侧栏 229px + 右栏 280px 并排 → 内容区 0px
目标 375px侧栏 off-canvas（translateX(-100%)）· 右栏 ≤1024 收起 / ≤768 隐藏
内容区占满 · 顶部 52px 顶栏（含汉堡）· 底部 4 项 tab
  • 侧栏改 position:fixed + transform:translateX(-100%)，去掉 min-width 的挤压效应
  • 补上 .mobile-header 的媒体查询，让汉堡真正出现
  • 底部 tab：全部 / 域 / 收藏 / 最近 / 更多，高 56px + 安全区

R2 · 侧栏：从 31 行到 9 行可见

现状6 视图 + 全部 + 4 分组头 + 30 分类（全展开）= 31 行，需滚动
目标5 范围 + 4 域（默认折叠）= 9 行，一屏放下
需要分类时：展开域，或直接用检索框
  • 域分组 collapsed 初值改 true，并提供「默认展开」偏好开关
  • 新增分类检索框：输入即过滤，命中域自动展开
  • 移除「发现」「分类」两个空壳视图项

R3 · 首屏：5 层 chrome → 2 层

现状StatsBar（统计+排序+视图+主题+设置）→ 时钟 → Google 搜索 → 站内搜索 → 卡片工具栏 → 卡片
目标搜索（含建议）→ 结果工具栏（排序/视图/批量/拖拽，紧贴列表）→ 卡片
统计与时钟下沉到侧栏底部；移除 Google 搜索
  • 合并 StatsBar 与 .cards-toolbar 为单一工具栏，置于结果列表正上方
  • GoogleSearchBar 移除（外站搜索并入命令面板，作为一条命令）
  • 首屏 chrome 上限：桌面 ≤ 2 行（搜索 + 工具栏）

R4 · 搜索：三个入口 → 一个主入口

主：站内搜索建议下拉 / 高亮 / ↑↓ / 回车打开 / 结果计数
高级：命令面板 Ctrl+K保留，覆盖跳转与操作
移除：GoogleSearchBar职责重叠，且是零引用的死代码候选
注意：V5 的搜索建议用 v-html 注入 <mark> 做高亮。既然要把它确立为唯一主搜索，就必须同时改为 DOM 分段渲染（createTextNode + <mark> 节点拼装），否则站点名/描述里的 HTML 会成为注入面。

实施分期

按「先止血、再正骨、后打磨」排序。每期结束都可独立上线，不留半成品。

修复移动端内容区 0 宽

侧栏改 position:fixed off-canvas；右栏 ≤1024 默认收起、≤768 隐藏；移除两侧栏在窄屏下的 min-width 约束。

依据：A1。实测 main.main = 0px，属功能不可用。

N2

让移动端顶栏真正渲染

为 .mobile-header 补 @media (max-width:768px){ display:flex }，汉堡按钮接入侧栏抽屉开合。

依据：A2。DOM 存在但宽度 0。
工作量 · 风险低
N3

新增移动端底部 tab 栏

四项：全部 / 域 / 收藏 / 最近，第五项「更多」打开抽屉。高 56px + env(safe-area-inset-bottom)，正文底部预留收敛到单一来源。

依据：A3。拇指可达性。
工作量 · 风险中
N4

视图状态进 URL

新增 /favorites /recent /feed /trash 路由；/category/:id 重定向到 /c/:id；activeNav 由路由派生而非独立存储。

依据：B2。让刷新、回退、分享、收藏全部生效。
工作量 · 风险中高
P1 · 正骨信息架构收敛，这是本轮的核心价值
N5

移除空壳视图项，统一为 5 个范围

删掉「发现」「分类」；侧栏范围导航固定为 全部 / 收藏 / 最近 / 聚合 / 回收站。选中分类不再改写视图状态。

工作量 · 风险低
N6

侧栏域分组默认折叠 + 分类检索框

四组 collapsed 初值改 true；新增检索输入框，输入即过滤分类并自动展开命中的域；提供「默认展开」偏好开关照顾老习惯。

工作量 · 风险低
N7

合并工具栏，chrome 下沉

StatsBar 与 .cards-toolbar 合并为单一工具栏，紧贴结果列表；排序 / 视图 / 批量 / 拖拽同处一行；统计与时钟移入侧栏底部。

N8

侧栏低频项下沉

主题换肤 / 导入导出 / 待办移出侧栏固定区，收进顶栏「更多」菜单或设置面板；侧栏底部只留「添加网站」。

导航项键盘可达

N11

「最近」语义对齐

风险与前置动作

前置动作：先把 V6 工作区改动安全搁置。当前工作区有 86 个未提交改动（V6 全部改造）。要回到 V5 根基，必须先留存它们 —— 建议打成一个补丁归档（git diff + 未跟踪文件打包）或提交到独立分支，不做丢弃式回退，保证随时可恢复。
N1 会改动布局模型。侧栏从 flex 子项改为 position:fixed 后，主内容区的左边距需要重新建立（原先依赖 flex 排布）。必须回归 1920 / 1440 / 1280 / 1024 / 768 / 375 六档宽度，确认三栏并排与抽屉切换都正确。
N4 会改动路由与状态来源。activeNav 从独立 ref 改为路由派生后，App.vue 里现有的双向 watch（Store ↔ 路由）需一并重构，避免出现「改路由触发改 Store、改 Store 又触发改路由」的循环。这是本期风险最高的一项。
N6 会改变老用户的肌肉记忆。域分组默认折叠后，「点一下就能看到分类」变成「先展开域」。缓解方式：检索框自动展开 + 提供「默认展开」偏好开关，把选择权交回用户。
数据层一律不动。本地覆盖层（nav-sites-overlay）、会话同步、探活分级、shared/categories.mjs 单一分类源，是本项目最值钱的资产。所有改造都建立在它们之上，不触碰。
上线路径已有自动化。npm run check 做站点体检、npm run publish 走「备份 → schema 门禁 → 构建 → 热更新 → 验证」。每期结束按此发布，不手工改线上数据。
