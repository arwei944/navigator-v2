# 浏览器同步扩展（v0.1）

把浏览器的历史、书签、当前标签页整理成**标准站点**，先送进导航站的
**临时工作区**，在后台确认分类与去重策略后再提升入主库。

> 关键约束：扩展**永远不会直接写主库**。它只调用 `POST /api/ingest`，
> 数据落在 `staging/` 前缀下；主库只有在后台点「提升」时才会变化。

## 安装

1. 打开 Chrome / Edge 的扩展管理页：
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
2. 打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本目录（仓库里的 `extension/`）。
4. 扩展图标出现后，点它 → 右上角「设置」。

## 配置

| 项 | 说明 |
|---|---|
| 导航站地址 | 本地：`http://127.0.0.1:3000`；线上：BotKeep / WorkBuddy 的域名 |
| 管理密钥 | 服务端 `data/admin-key.txt` 的内容（线上需与部署的 `SITES_ADMIN_KEY` 一致） |
| 默认筛选 | 时间范围、最少访问次数、单次最多采集 |
| 域名黑名单 | 每行一个，命中即跳过（导航站、搜索页、公司内网等） |

点「测试连接」会调用 `GET /api/ingest?categories=1`，
同时验证地址、密钥与分类表 —— 比只打开首页可靠。

## 使用

1. 点扩展图标，选择来源与筛选条件，点「扫描浏览器」。
2. 扩展会在本地先筛一遍，然后请求服务端生成预览：
   - 每条会带上**标准站点字段**（名称、网址、描述、分类、颜色、首字母、用途等）；
   - 与主库同网址的条目标「主库已有」并默认不勾选；
   - 浏览器内部页面、本机地址、无效域名会进入「非法」计数。
3. 在列表里逐条确认，或用「批量设置分类」一次性调整。
4. 点「保存到临时工作区」。
5. 点「去后台处理」进入导航站后台的「浏览器工作区」，选择冲突策略后提升。

## 分类与筛选

- **分类**以服务端返回的分类表为准（4 组 25 个子分类），扩展端只做展示与覆盖，
  避免两套规则给出不同答案。
- 自动分类规则按域名与标题关键词匹配（GitHub → 编程、Binance → CEX、
  Figma → 设计……），匹配不到时落到 `starter`。
- **筛选**在扩展本地完成：时间范围、最少访问次数、来源、关键词排除、域名黑名单。
  上传的条目越少，后台确认越轻松。

## 隐私与安全

- 只请求你填写的导航站地址；不经过任何第三方服务。
- 管理密钥保存在本机 `chrome.storage.local`，不会写入日志或发送到别处。
- 采集范围由你勾选；扩展不会在后台自动上传。
- 原始数据只进临时工作区，可整批丢弃，不影响现有站点。

## 故障排查

| 现象 | 处理 |
|---|---|
| 「未配置」 | 先在设置里填写地址与密钥 |
| 「连接失败」 | 服务是否启动；地址是否带 `http(s)://`；密钥是否与服务端一致 |
| 401 | 密钥不一致：本地 `data/admin-key.txt`，线上是部署环境变量 `SITES_ADMIN_KEY` |
| 保存后主库没变化 | 这是预期行为：批次在临时工作区，需要去后台点「提升」 |
| 想撤销 | 后台「浏览器工作区」里点「丢弃批次」，主库不受影响 |

## 权限说明

| 权限 | 用途 |
|---|---|
| `history` | 读取浏览历史（仅在点「扫描」时） |
| `bookmarks` | 读取书签 |
| `tabs` | 读取当前窗口标签页 |
| `storage` | 保存连接配置 |
| `contextMenus` | 右键「把当前页加入临时工作区」 |
| `host_permissions` | 访问你配置的导航站地址 |
